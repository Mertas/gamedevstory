# PLAN-45: Диффы по сокету (трафик)

Статус: **сделано, v1.42.0, 03.10.2026.** Направление босса: «сокращать кратно; слать диффы, только произошедшие события, через сокет».
Внедрено: кадры-диффы `{state2}`, кольцо догона (64), пауза фоновых вкладок, схлопывание эмитов 250 мс,
`permessage-deflate` для крупных, локальный возврат попапа (серверный пульс убран, `get_state` при входе убран).
Вопросы UX (троттлинг/фон) приняты рекомендованными вариантами — переключаются одной константой.

## Проблема (замерено)

Каждый тик сервер шлёт **полный снапшот** партии каждой вкладке. Большой сейв = 1.79 МБ JSON.

| Режим | Замер 03.10 (probe, реальный прод-сейв) |
|---|---|
| Покой (событие висит, пульс 1.5 с) | 2.8 МБ/с ≈ 231 ГБ/сутки |
| Скорость 5× | **8.6 МБ/с ≈ 707 ГБ/сутки на вкладку** (60 снапшотов по 1.7 МБ за 12 с) |

Прод-сказано: 131 ГБ за 2 дня, 99.9% — `/ws`. Разбор сейва: 77% веса — архив игр
(`game.history`, append-only), 14% — чат/лог/почта (кольцевые), меняется за тик <1% (деньги/фанаты/статы/прогресс).

## Решение: версионированный поток кадров-диффов

**Инвариант:** полный снапшот — только вход/восстановление; дальше — кадры «что изменилось».

### Сервер

1. **Зеркало + версия.** В `GameServer`: `ver` (номер последнего кадра), `mirror` (structuredClone
   состояния после последнего кадра), кольцо последних 64 кадров `{ver, ops}`.
2. **Диффы.** На каждый emit: `ops = diff(mirror, current)`; зеркало перезаписывается. Дифф —
   построчный обход: объекты по ключам (`s` — set, `d` — delete), массивы: общий префикс/суффикс →
   одна `a`-операция (splice); отдельный случай «сдвиг головы + хвост» (кольцевые чат/лог/почта:
   `splice(0,k)` + push не должен пересылать 800 сообщений) — детект по ссылке-якорю головы +
   полная сверка перекрытия, иначе fallback — замена массива. Пресс-пересадка (правка середины
   `history[i].reviewMessages`) — точечная замена элемента, уже покрыта префиксом/суффиксом.
3. **Формат кадра:** `{type:'state2', base:ver-1, ver, ops:[['s',путь,значение],['a',путь,start,del,items],['d',путь]]}`.
   Кадр строчкой кэшируется (одна строка на всех клиентов, стоящих на том же base).
4. **Кольцо для догона.** Клиент, отставший (фон/сеть), догоняет конкатенацией кадров из кольца;
   отстал больше кольца — получает полный снапшот (с `ver`).
5. **Per-socket**: `myVer` (на какой версии клиент) + `hidden` (фон). `sendSafe` при
   backpressure кадр не пропускает молча — клиент просто остаётся на своей `myVer` и получает
   догон/полный; рассинхрона нет.
6. **`get_state`** — теперь полный снапшот **только этому сокету** (сейчас — широковещание).
7. **`import`/`new_game`/ошибка синка** — всем полный снапшот, `ver` сбрасывается.
8. **Пульс убирается** (был: пока событие висит — полный снапшот раз в 1.5 с «на случай потерянного
   клика»). Замена — клиентский таймер (см. ниже); трафик в простое → ноль.
9. **`perMessageDeflate` (порог ~4 КБ)** — сжатие крупных кадров (первый снапшот 1.8 МБ → ~0.3 МБ,
   meta), мелкие кадры не трогаем.
10. **Троттлинг тикерных эмитов** (окно 250 мс при скорости ≥5×): кадры «схлопываются»; действия
    игрока эмитят мгновенно. На 1–4× не влияет вовсе.

### Клиент

1. `applyOps` (в `src/shared/sync.ts`, рядом с серверным `diff`): применяет кадр к состоянию
    иммутабельно (копии только по пути операции) → zustand-селекторы и цепочка ссылок
   (чат-подпись `chatSig`) продолжают работать.
2. Guard: `msg.base !== myVer` → послать `get_state` (полный снапшот) и продолжить.
3. **Видимость:** клиент шлёт `{type:'visibility', visible}` по Page Visibility API. Фон → сервер
   копит кадры (без отправки), возврат → догон. (Сейчас фоновые вкладки едят как активные.)
4. **Переоткрытие попапа вместо серверного пульса:** при закрытии попапа события — локальный таймер
   3 с; если событие на сервере осталось (клик потерялся при обрыве WS) — попап возвращается
   локально. Семантика та же, трафик — ноль.

## Не трогаем

- Механики, формулы, сейв-формат, миграции — ноль изменений.
- Игровой цикл: тикер/события/чат те же, меняется только транспорт состояния.
- REST/авторизацию/инвайты.

## Тесты

- `test/sync.test.ts`: diff/apply — fuzz (случайные мутации больших структур: push/сдвиг головы/
  правка середины/вложенные) → `apply(ops, old)` deep-equal new; размеры кадров на эталонном кейсе.
- `test/server.test.ts` + новый фрейм-тест: кадры после тиков (не полные), догон из кольца,
  отставший сверх кольца → полный, `import` → сброс, `get_state` → только этому сокету.
- Спец-кейсы: чат-кольцо (трим+push) — кадр < 1 КБ; пресс-пересадка — точечная правка.

## Метрика после (замер 03.10.2026, v1.42.0, тот же probe)

- Покой: **0 байт/с** (пульс убран; фоновые вкладки молчат).
- Скорость 5×: **0.42 КБ/с**, кадры по ~113 байт (было 8.6 МБ/с и 1.7 МБ на кадр) — **×~20000**;
  ≈35 МБ/сутки вместо ~707 ГБ на активную вкладку.
- Вход в партию: один полный снапшот (со сжатием меньше) + один при переподключении.
