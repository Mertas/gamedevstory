# 49. Сага «Синяя Комета» в игре — эскиз внедрения (черновик)

**Статус:** черновик, на согласование механик. Код игры не тронут.
**Материалы:** план 47 (тексты), стенд `quest-test` (45 узлов, заглушек 0), арты `comet-*` (34), лица `face-*` (9) — готовы.
**База:** v1.48.0 (`c1a386a`), 485/485.

## 1. Цель

Сагу в игру — как **скрытую главную линию партии**: главы приходят по мере игры,
выборы ветвят судьбу студии, у истории 6 авто-эпилогов. Каждая глава — большой
квест-попап с артом 16:9 и жетоном лица персонажа (левый верх, как на стенде).

## 2. Что уже есть (используем, не переделываем)

- Движок сюжетных линий `src/core/systems/story.ts`: шаги, `pendingEvent {type:'story'}`,
  `resolveStory` (эффекты, вехи), эпилоги по таймеру, правило «одна история за раз».
- Контент-формат `src/shared/storylines.ts`: шаги `{title,text,options}` + плейсхолдеры.
- Родовые пары `src/shared/gender.ts`: `{он/она@ключ}`; ключи ролей ({Скептик}…{Герой},
  {Партнёр}) уже заведены; пол ГГ/партнёра — из v1.48.0.
- Попапы с арт-баннером (PLAN-46): `MessageBox` → `QuestBox`; карта `questArt.ts`
  (ключ → emoji/accent + `/quests/<key>.png`, фолбэк-плитка).
- Сейвы: `saveVersion` + миграции (`src/core/migrate.ts`). Время — дни (год = 365).

## 3. Что строим

### 3.1 Контент: saga.json (стенд) → формат игры
- Конвертер `tools/…` (черновик: `build-saga.mjs`): `saga.json` → `src/shared/saga-data.ts`
  (расширенный формат: шаги, cond-варианты, эффекты, вставки).
- Автопроверки при сборке: битые ссылки, недостижимые узлы, неизвестные флаги
  (аналог `check-saga.mjs` стенда).
- `[СУММА]` / `[НАГРАДА]` / `[ШТРАФ]` остаются плейсхолдерами до этапа чисел.

### 3.2 Движок: `src/core/systems/saga.ts` (рядом со story, не ломая арки)
- Состояние: `state.saga = { step, flags, scales, roles, epilogue }`;
  `pendingEvent` расширяется типом саги (как `'story'`, отдельный резолвер).
- Пейсер: старт ≈ при ≥1 релизе; глава раз в K дней при выполнении условия акта;
  кризисные варианты (⚡) — через cond, не через отдельные ветки.
- Варианты: `cond` по состоянию (деньги/фанаты/флаги/шкалы/штат); недоступное —
  скрыто или серым (решение в §5).
- Вставки: условные фрагменты текста (в т.ч. отсылки к аркам «мечта/выгорание»).
- Эпилоги: 6 вариантов, авто по флагам/шкалам после S23 — отдельные попапы.

### 3.3 Роли ({Скептик}, {Мечтатель}, {Технарь}, {Юрист}, {Старожил})
- Роль = сотрудник из штата; фиксация при первом появлении саги; при увольнении —
  замена (роль живёт, человек меняется). Пол — `staff.gender`.
- В текстах: `{Скептик}` → имя выбранного; родовые пары раскрываются как на стенде.

### 3.4 Шкалы (скрытые)
- `ШУМ` (тихо/шумно/научно-публично), `СОВЕСТЬ`, `ДОВЕРИЕ`×5 NPC (Вера, Мороз,
  Каспер, Глеб, Ростоцкий). Числа — внутри саги; «репутация» — производная от флагов,
  отдельной системы не строим.
- Показ: по умолчанию — только текстом в сценах/эпилогах (см. §5).

### 3.5 UI
- Арты глав: ключи `comet-sN` / `comet-iN` / `comet-eN` → карта артов (+фолбэки).
- **Жетон лица** поверх арт-баннера (левый верх): по узлу — `face-*.png`; нет файла —
  фолбэк (скрыть жетон). Геометрия и стиль — как в стенде (104×104, offset 15).
- Варианты-кнопки: с блокировкой по cond (серая + пояснение), как на стенде.
- Эпилог-финалы: показ по завершении.

### 3.6 Сейвы
- Миграция: `saveVersion → 15` (новое пустое поле саги; старые сейвы не ломаются).
- Старые партии: сага подхватывается при ≥1 релизе — то есть задним числом сразу.

### 3.7 Числа/баланс (отдельный проход, после механик)
- `[СУММА]/[НАГРАДА]/[ШТРАФ]` → значения; ритм K; пресеты сложности.
- Калибровка: по ощущениям партии (в игре), стенд — для текстов и развилок.

## 4. Этапы

| Этап | Содержание | Выход |
|---|---|---|
| Э1. Вертикальный срез | S1–S3 в игре: пейсер, роли, cond, жетон, сейв-миграция, выключатель | живая сага в игре (за флагом) |

## 5. Решения (утверждены юзером)

1. **Роли** — фиксируются при старте саги; роль живёт до увольнения (замена — другой сотрудник).
2. **Ритм глав** — ~раз в 180–230 дней (≈полгода) при условии акта; вся сага ≈22–28 лет.
3. **Показ шкал** — скрыто; только намёки в текстах и эпилогах.
4. **Старые сейвы** — подхват сразу при ≥1 релизе.
5. **Выключатель** — флаг сборки на время разработки; после релиза сага для всех
   (отдельный режим «без саги» не делаем).
6. **Э1 согласован — старт.**

## 6. Риски

- **Конкурс событий**: сага vs арки vs процедурные квесты (одно событие за раз) —
  нужны приоритеты, чтобы сага не забивала личные истории и не «голодала».
- **Длина**: 45 узлов на партию — следить за темпом (не утомить).
- **Формат/сейвы**: расширения `StoryState` — только через миграцию, арки не трогаем.
- **Ассеты**: `public/quests/*.png` (арты+лица) ещё не в git — закоммитить к релизу саги.

## 8. Э2 (полный контент в игре) — СДЕЛАНО

- **Контент**: все 45 узлов (акты I–VI, 5 интерлюдий, 6 эпилогов) в `src/shared/saga-data.ts` (109 КБ);
  эпилоги E1–E6 — финальные узлы (`final: true` → текст + кнопка «Конец»), конвертер допускает их без choices.
- **Эпилог**: хаб EP со стенда игроку не показывается — заменяется авто-выбором по правилам 1–7
  (`sagaEpilogFor`; пороги секрета в `CONFIG.SAGA.EPILOG`; у Виталика в контенте только −1 — порог «не терял
