# PLAN-18: Пользователи, вход и сохранения в базе

Запрос: начальное окно (регистрация / вход / восстановление пароля по почте), у каждого
пользователя своя игровая сессия, пользователь Mertas / 123456, «Пуск» → выход в начальное
меню, сохранения пользователей в БД + список сохранений, новая игра — выбор 2 сотрудников
из начального пула и название студии.

## Решения (согласованы 11.09)
- Почта: dev-режим — код восстановления показывается на экране и в консоли сервера;
  SMTP-заготовка (nodemailer, тестовые данные в .env) — включается при выкладке в интернет.
- Сохранения: много на пользователя; «Новая игра» = новое сохранение (название студии + дата);
  автосейв пишет в текущее.
- Пул для выбора двух сотрудников: все «доступные сразу» из контентной БД.
- Текущая партия (21-й год): удалить; файл data/save.json выводится из игры.

## Архитектура
- `data/users.db` (node:sqlite, RW): `users(id, login, email, pass_hash, salt, created)`,
  `sessions(token, user_id, created, expires)`, `saves(id, user_id, studio_name, created,
  updated, payload)`, `resets(user_id, code_hash, expires)`.
- Пароли: node:crypto scrypt + соль (новых зависимостей не нужно).
- HTTP (тот же Express :3001, `/api/*`): register / login / logout / me / reset-request /
  reset-confirm / saves (list/load/delete). Cookie httpOnly + SameSite=Strict.
- WS: подключение авторизуется токеном сессии → `SessionRegistry` (Map userId → GameServer):
  у каждого пользователя своя партия и свой тикер.
- Сохранение: `DbSaveStore` (list/load/save/delete) в users.db; GameServer пишет через него
  (файловый SaveManager остаётся для тестов/не-пользовательского режима).
- UI: экран входа (React-корень до рабочего стола): вход / регистрация / восстановление;
  после входа — рабочий стол; «Пуск» → «Выход» (logout → экран входа).
- Новая игра: экран «Студия» — название студии + выбор 2 сотрудников из пула →
  `newGame(seed, { staffIds, studioName })`; имя студии видно в трее и в списке сохранений.

## Этапы
1. Ядро: `newGame(seed, opts)` с студийным именем и стартовой парой; `studioName` в GameState
   (+ миграция старых сейвов); тесты ядра.
2. users.db + UserService (scrypt, сессии, reset-коды) + REST `/api/*` + тесты.
3. WS-авторизация + SessionRegistry (своя партия на пользователя) + запись в БД.
4. UI: экран входа/регистрации/восстановления, «Выход» в «Пуске», экран выбора сотрудников
   и названия студии, список сохранений (загрузить/удалить).
5. Проверки: typecheck / check / build + живой прогон под Mertas / 123456.
