# 06. Железо и платформы

> Источник: research/01 §8 + Appendix E, research/02 §7, research/03 §9.

## 1. Правила

- Для разработки под консоль нужна **лицензия** (кроме PC). Чем новее/дороже консоль — тем выше доход за копию (и тем дороже разработка).
- **PC никогда не снимается с производства**; консоли от **Mini Status и новее тоже никогда** не снимаются.
- О снятии консоли игрок предупреждается **за 3 недели** (реализовано так: слух и красный таймер).
- Создание своей консоли снимает с рынка вашу предыдущую собственную консоль.
- Рост базы консоли: ~100K новых владельцев за каждую выпущенную игру (яп. вики).

## 3. Своя консоль

**Требования:** офис 3 + минимум 1 активный Инженер железа. Долгая разработка (быстрее с высокими статами); **релиз консоли в декабре** даёт заметно большую базу (июльский — слабее). Своя консоль никогда не снимается; база стартует от фанатов студии (фанаты/25, без потолка) и растёт +93K за каждую игру под неё (v1.34.0).

## 4. Динамика рынка

- Базы растут медленно со временем + ~100K за игру (наша и конкурентов).
- После выхода вашей/Каройской консоли рост остальных замедляется (яп. вики).
- Karoisoft «отвечает» своими консолями (Юпитер 512, GameJohn) — они легко обходят вашу по базе; это потолок для эндгейма (ваша ультимейт-консоль — последний вызов).
- Рекомендация сообщества: следить за **% доли рынка**, а не гнаться за новейшей консолью — на «народных» консолях (Game Kid, PlayStatus) продажи стабильнее, лицензии дешевле.

## 5. `[наше]` — чего не делаем в MVP

- Две одновременные собственные консоли — нет.
- Модификации консоли после выпуска (скины) — M7+.
- Ценообразование игр под консоль — нет (как в оригинале).

## 6. M8 (16.09.2026): окно «Железо» — пороги, таймеры, форма своей консоли

- Таблица консолей: статус показывает **пороги** (Юпитер 512 — «Гран-при N/2»; GameJohn — «Гран-при N/5 ·
  лучшая игра X/20M»), **даты появления** («появится 12 июня 1990 (через N нед.)») и **таймеры снятия**
  («снятие через N нед.», красным — последние 3 недели). Раньше непоявившиеся консоли показывались как «да»
  с активной кнопкой (сервер отклонял покупку — теперь и UI честный).
- Форма своей консоли: **живая смета** (итог/срок пересчитываются от выбранных компонентов —
  раньше в кнопке была захардкожена цена базовой сборки), **чек-лист требований** (офис 3 / хардвер-инженеры /
  деньги) с причинами блокировки, прогресс постройки с «осталось ~N нед.».
- **Единый источник** `src/shared/consoles.ts`: календарные даты (`dateToDay`), пороги событийных консолей
  (`EVENT_CONSOLE_REQ` — из CONFIG), компоненты своей консоли, срок (`ownConsoleDays`). Движок и UI
  больше не могут разойтись (как раньше дублировались таблицы компонентов и формула срока).
- Известный долг (закрыт в v1.34.0, см. §7): готовая СВОЯ консоль не появлялась в мастере разработки —
  в мете/справочнике платформ не было записи `own-*`, и релиз под неё не проходил.

## 7. v1.34.0 (28.09.2026): своя консоль доступна в разработке

- Причина: `consoleById` искал только в рыночном справочнике `CONSOLES` — `own-*` не находился,
  мастер/релиз его не видели. Решение — резолвер `consoleDataFor(state, id)` (рыночные из справочника,
  свои — синтетика из `state.consoles[id]`) + `allConsoles(meta, game)` для UI (мастер, «Железо»,
  архив, карточка игры, чат/автопилот).
- Множитель по компонентам (утв. игроком 27.09): `ownConsoleMult` — ×8 (16-бит + картридж) …
  ×29 (Чип «Картошка» + Перфокарты); тот же множитель = стоимость разработки и цена за копию.
  Имя/чип/носитель сохраняются при завершении стройки (старые сейвы — «Своя консоль», ×8).
- Стартовая база (утв. игроком 28.09): `ownConsoleStartBase = фанаты/25` (без потолка) — фанаты студии
  покупают консоль; дальше +93K за каждый релиз под неё. Миграция v10: у старых сейвов база 0 → пересчёт.
- Живой смоук: список мастера «Мечта · база: 733K · множитель ×14» → «Итого: (20K + 30K) ×14 ×1 ×2.44
  = 1 708K» → старт: касса 5000→3292, лог «Старт разработки: Table × Pirate (Мечта, normal, 1708K, комбо F)».
