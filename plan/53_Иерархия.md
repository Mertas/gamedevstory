# PLAN-53. Иерархия сотрудников (16.10.2026)

## Зачем
Статы сотрудников выше 100 сейчас линейно входят в статы игры и ломают баланс.
Вторая ось развития — организационное дерево: руководитель раздаёт излишек статов
подчинённым с пессимизатором. Игрок строит структуру студии, а не просто покупает людей.

## Решения босса
1. «Из сотрудников можно делать иерархию: владелец — самый главный, под ним можно делать
   любое дерево (перетаскиванием аватарок в новом приложении)».
2. «Большие (больше 100) статы сотрудников больше не влияют на статы игры, но распространяются
   с пессимизатором на подчинённых».
3. «Кап на кол-во сотрудников убираем, делаем расширение по 1 месту, каждое последующее место дороже».
4. «Все условия по 2-му офису пусть включаются при найме 5-го сотрудника, по 3-ему — при найме 8-го».
5. Ответы на вопросы 16.10.2026:
   - в игру идут первые 100 каждого стата, излишек — только в иерархию;
   - излишек считается **по каждому стату отдельно**, пессимизатор жёсткий (стартово ×0.25,
     формула в CONFIG — потом калибруем);
   - прямым подчинённым — полный бонус, второму уровню — ×0.5 за глубину;
   - бонус может поднимать подчинённого выше 100, и его излишек раздаётся дальше («башни растут»);
   - офисы как переезд упразднены: только места, условия офиса 2/3 включаются при найме 5/8.
6. Комбы v-team (полные команды) — отдельный слой; бонус применяется только после завершения игры.
   В этом этапе не делаем.

## Механика
- Дерево: `Staff.bossId` (`null` = подчиняется владельцу). Владелец — ГГ (`hero`), его нельзя
  переподчинить, он раздаёт свои излишки как любой руководитель.
- Эффективные статы: `eff(node) = base + Σ по предкам: max(0, eff(предок) − 100) × K × 0.5^(d−1)`,
  где `d` — расстояние до предка. `K = HIERARCHY_EXCESS = 0.25`.
- Вклад в игру (dev): `min(eff, 100)` на каждый стат — роли, универсал, предложение сценариста.
- Увольнение руководителя: его прямые подчинённые переходят к его руководителю (или владельцу).
- Места: `state.seats` (старт 4). Найм возможен при `staff.length < seats`.
  Цена следующего места = `SEAT_PRICE_BASE × SEAT_PRICE_MULT^(seats−4)`:
  5-е — 250K, 6-е — 325K, 7-е — 423K, 8-е — 550K, 9-е — 715K…
- Офисы: `officeLevel` = 2 при 5 сотрудниках, 3 при 8; растёт и не падает.
  Переезд за деньги удалён, `OFFICE_CAPACITY` удалён. Условия (найм-методы, слоты мерча,
  обучения и т.п.) продолжают читать `officeLevel`.
- SAVE_VERSION 22: `seats` (max(4, staff.length)), `bossId` (null), `officeLevel` поднять по числу.

## UI
- Новое приложение «Иерархия»: дерево с аватарами и линиями, drag&drop
  (на сотрудника — подчинить, на владельца — вернуть в корень), эффективные статы с бонусом,
  счётчик мест + «Купить место».
- Найм и вкладка «Команда»: `staff.length / seats`, кнопка покупки места; переезд офиса убран.
- Справка: раздел «Иерархия».
