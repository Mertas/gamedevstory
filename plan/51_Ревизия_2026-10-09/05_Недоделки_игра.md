## Резюме

- Всего: **1 P0 / 3 P1 / 7 P2 / 7 P3**.
- **P0:** арка «Оффер» может безвозвратно уволить главного героя (и партнёра) — story.ts не знает про `hero`/`partnerPct`, а `removeStaffQuiet` удаляет запись из `staff` и `hiredIds`; защита есть только в `fireStaff`.
- **P1:** 36 из 79 типов игр навсегда недоступны — условие «нужен тренинг» сверяется как подстрока с сырым японским названием тренинга, 8 канонических id (`pinball`, `meditate`, `stroll`, `concert`, `netsurf`, `college`, `shorttrip`, `longtrip`) не совпадают ни с одним; заодно недостижимы 4 верхних звания книги рекордов.
- **P1:** секретный эпилог E6 «Двойной финал» недостижим: порог доверия Жанны = 2, а в саге ровно два эффекта доверия `+1`, и оба — взаимоисключающие выборы одного узла S11 (максимум +1).
- **P1:** письма фанатов считают тон по старой шкале /40 (score≥25 → всегда «восторг»), hate/neutral-письма и 2 из 4 стилей недостижимы, а текст-заготовка показывает «N/40» при заголовке «N/100».
- **P2:** эпилоги личных арок приходят через «недели», а движок считает дни (8 дней вместо 8 недель); 15 флагов саги никто не читает (в т.ч. все 4 «реставрации» S15 — выбор без последствий), артефакты и шкалы culture/biz вообще не отображаются.
- **P2:** «Отказаться» от коробки (S13#4) ведёт в S13b/S14, где коробку всё равно вскрывают, а Вера «присутствует» после «уходит, оставив ключ»; флаг «без партнёра» фиксируется только на старте саги и не обновляется при уходе партнёра.
- **P2:** окна «Исследования» и «Маркетинг» до сих пор пишут «контракты/Gamedex — в разработке», хотя обе механики полностью работают; мини-игра на 50% разработки в проде живёт во внешнем `E:/MY/gds-minigames`, которого нет в репозитории и не отдаёт nginx.
- **P3 (7 шт.):** консоли не локализованы (English в русском UI против plan/11 §2), fallback-генератор имён собирает английские названия, в справке нет раздела «События» (обещан plan/44 §5), 14 `hint` в `storylines.ts` не рендерятся, `awards.worst` не инкрементируется, нет технологий и ачивок из plan/07 §3/§5, «Исследования» показывают английские имена жанров/типов.

## Находки

### P0-1 — Арка «Оффер» может навсегда убрать главного героя (и партнёра) из студии
- **Где:** `src/core/systems/story.ts:55` (`personCandidate` — фильтр `busy`/`homeWeeks`/`lv>=2`, без проверки `s.hero` и `s.partnerPct`); `src/core/systems/story.ts:98` (`removeStaffQuiet` — `state.staff = state.staff.filter(...)`, `state.hiredIds = ...`); вызовы `src/core/systems/story.ts:332` и `src/core/systems/story.ts:338`; триггер `src/core/systems/story.ts:229`. Защита — только в `src/core/systems/staff.ts:214` («Это основатель студии — уволить его нельзя») и `:215` (два способа для партнёра), но арка их обходит.
- **Что:** арка «Оффер» выбирает кандидата Lv2+ среди свободных; ГГ (`staff[0]`, `id:'hero'`, стартует Lv1 в профессии) после первого левелапа проходит фильтр и часто оказывается сильнейшим — значит, именно он получает «предложение конкурентов». Далее любая ветка, кроме «Повысить оклад» (успешный `talk` — 40 %, `letgo`), вызывает `removeStaffQuiet` и физически удаляет ГГ из `state.staff` и `state.hiredIds`. Для партнёра то же самое: он исчезает без выкупа доли и без ренты, `state.partnerRentPct` не меняется.
- **Последствие:** игрок необратимо теряет собственного персонажа («вечного сотрудника», PLAN-48) и/или партнёра — это ломает премису партии, диалоги саги (`sagaNameMaps` подставит «Вы»), чат (автор-ГГ), правила «уволить нельзя» и «партнёр — только два варианта». Восстановить можно лишь загрузкой старого сейва.
- **Действие:** исключить `s.hero` и `s.partnerPct` из `personCandidate` (и из парных арок — `pairTop2`/`pairByTop`/`pairByLevel`) либо вызывать `fireStaff`-подобный гейт внутри `removeStaffQuiet`; добавить тест «арка offer не берёт ГГ/партнёра». (S)

### P1-1 — 36 из 79 типов игр недостижимы: id тренинга не совпадает с сырым именем тренинга
- **Где:** `src/core/systems/progression.ts:115` (`state.unlockedTrainings.push(t.name)` — пушится сырое имя из БД, напр. «パチンコ pachinko»); `src/shared/rules.ts:25` (`x.toLowerCase().includes(training.toLowerCase())`); тот же чек в `src/core/systems/dev.ts:84` (старт проекта) и `src/ui/apps/code/Wizard.tsx:105` (список типов); данные — `data/gamedev.db` (`types.unlock_training` = канонический id, `trainings.name` = японско-английское имя).
- **Что:** `unlockedTrainings` хранит `t.name` (напр. `パチンコ pachinko`, `瞑想 meditation`, `散歩 walk`, `音楽ライブ live music`, `ネットサーフィン surfing`, `大学で勉強 university`, `国内旅行 domestic trip`, `海外旅行 overseas trip`), а условие ищет подстроку канонического id (`pinball`, `meditate`, `stroll`, `concert`, `netsurf`, `college`, `shorttrip`, `longtrip`). Совпадают только 34 типа из 70 «тренинговых»; 36 (Виртуальный питомец, Хоррор, Поезда, Магазинчик, Книжный магазин, Египет, Архитектура, Адвокаты, Монстры, Старшая школа, Школа, Война, Милые, Огры, Мода, Ковбои, Подковы, Мини-юбки, Грибы, Пончо, Шахматы, Маджонг, Танцы, Фитнес, Плавание, Автоспорт, Сумо, Бейсбол, Борьба, Формула-1, Пинбол, Автоматы, Гавань, Путешествия во времени, Шпионы, Знаменитости) не открыть даже при пройденном тренинге. Обход `comboKey`/`openedCombos` (`rules.ts:23`) работает только для пар, уже открытых в аккаунте, — для нового игрока бесполезен.
- **Последствие:** почти половина типов контента не рисуется в мастере и отклоняется сервером; попутно недостижим потолок книги рекордов: 20×43 = 860 комбо при 1580 возможных, т.е. звания от 950 комбо (`src/shared/rank.ts:64`–`:67`, вплоть до финального «Нолан Бушнелл») не получить.
- **Действие:** хранить в `unlockedTrainings` канонический id тренинга (брать из `TrainingId`, а не `t.name`) либо нормализовать сравнение (карта «имя → id» один раз); заодно миграция для старых сейвов; тест «каждый тип с `unlock_training` открывается после соответствующего тренинга». (M)

### P1-3 — Письма фанатов: тон считается по шкале /40, hate/neutral недостижимы, в тексте «N/40» при заголовке «N/100»
- **Где:** `src/core/systems/mail.ts:63` (`score >= 25 ? 'love' : score <= 19 ? - **Что:** после PLAN-30 `game.score` — это уже /100 (30..100), но письма сравнивают его с /40-порогами. При итоге ≥30 условие `score >= 25` истинно всегда ⇒ все письма «восторг/ностальгия»; `hate` (≤19) и `neutral` (20–24) недостижимы, стиль `rant` и `ideas` не появляется. Плюс fallback-текст собирает строку вида «…это 85/40…», которую игрок видит, пока LLM не перепишет письмо (а без ключей GigaChat письмо остаётся заготовкой — `src/server/mail.ts:75`).
- **Последствие:** мёртвый контент (2 из 4 стилей писем, штрафные/нейтральные письма, `LETTER_HATE_*`), и явное противоречие чисел в одном окне («85/100» в шапке и «85/40» в теле).
- **Действие:** пороги — 75/45 для /100 (или сравнивать `score/2.5`), а из шаблонов заменить «/40» на «/100»; обновить `test/engine.test.ts:634`–`:639` (там зашиты невозможные 15/22/33). (S)
