## Механика

- В разработке (`devTick`) при `progress >= 0.5` (флаг `mg50` не выставлен, событий нет) —
  событие `pendingEvent = { type: 'minigame', gameId: '' }`. Пока событие висит, игровое
  время стоит штатной паузой тикера (как бусты/дизэстеры).
- Сервер добирает `gameId` из **ротации мешком без повторов**: аккаунт, `user_flags['mg_bag']`
  (все четыре по разу в случайном порядке, потом новый круг; на стыке кругов подряд не повторяется).
- Формат: модальное окно «МИНИ-ИГРА» поверх стола. Кнопки пропуска **нет**; партию можно
  **закрыть** («✕ Закрыть» → подтверждение «ТОЧНО? Штраф −2 PR») — это максимальный штраф,
  результат не засчитывается. После прохождения или закрытия — «Продолжить».
- Результат игры (0–100%) уезжает из iframe в GDS; эффект (маленькие числа, подстроим):
  **≥70% → +3 PR · 40–69% → без изменений · <40% → −2 PR** (пол — 0). Строка в журнал игры.
- Автопилот (если включён): мини-игру не играет — закрывает нейтрально (0), в лог
  «мини-игра пропущена (автопилот)».
- Возможные следующие врезки (33%, 66%) — задел, сейчас только 50% (как просил).

## Архитектура

- **Песочница (`E:/MY/gds-minigames`)**: embed-режим одной страницы —
  `?embed=1&g=g104&p=<base64url>&snd=0|1` прячет меню/панели/историю, открывает игру сразу,
  параметры отдаёт через `window.__mgParamsInject`, результат — `window.mgDone(pct, rank)` →
  `postMessage` родителю. Звук: `snd=0` глушит (у босса GDS без звука).
- **GDS**: модалка с iframe на `/lab/` (относительный путь — локально отдаёт vite-плагин из
  `E:/MY/gds-minigames` (env `GDS_LAB_DIR`), в проде уже есть nginx). Мост:
  iframe → `{source:'gds-mg', type:'done', pct, rank}`; GDS → action `resolve_minigame {pct}`.
- Клиент и сервер используют одну общую таблицу ротации/настроек (`src/shared/minigames.ts`).

## Тесты и приёмка

- Живой прогон песочницы в embed-режиме — headless Chrome, кадры.
- GDS: typecheck/lint/тесты; живой прогон — босс сам (локально, `pnpm dev` + `pnpm server`).
