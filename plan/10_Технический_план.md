# 10. Технический план

## 1. Решение по стеку

**Рекомендация: клиентское веб-приложение** — React + TypeScript + Vite, чистая игровая логика (без зависимостей от UI), сохранения в localStorage/IndexedDB.

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **React + TS + Vite (клиент)** | Быстрая итерация UI; вся логика — чистый TS, легко тестировать; портативно; наш стек | Нет сервера (и не нужен) | ✅ **Берём** |
| React + Node/Express backend | — | Лишняя сложность для одиночной игры | ❌ |
| Electron | Нативный вид | Тяжёлый, лишний | ❌ (можно позже обернуть) |
| Canvas/pixi.js для офиса | «Картинка как в оригинале» | Замедляет MVP | ⏳ Позже, как полировка (M7) |

Ограничения среды (проверено ранее): **только Node 22** (на v20 сегфолты), pnpm. Python/GPU не нужны — игра чисто клиентская.

## 2. Архитектура

```
src/
  core/                 # чистая логика, НИКАКОГО React
    types.ts            # все типы состояния (State, Staff, Game, Console...)
    rng.ts              # seeded RNG (mulberry32) — детерминизм для тестов
    data/               # контент-таблицы (JSON/TS): жанры, контенты, темы,
                        #   консоли, сотрудники, события, контракты, реклама,
                        #   исследования, офисы, журналы
    formulas.ts         # ВСЕ формулы (см. 09_Формулы_и_данные.md)
    systems/            # по системе на модуль:
      staff.ts          # найм, уровень, усталость, смена карьеры, обучение
      dev.ts            # пайплайн разработки, очки, баги, дедлайн
      release.ts        # релиз, рецензии, продажи по месяцам
      market.ts         # фанаты, хайп, реклама, популярность жанров
      hardware.ts       # платформы, лицензии, базы, пресс-конференции
      contracts.ts      # заказы
      events.ts         # случайные события
      research.ts       # исследовательские очки, анлоки
      economy.ts        # деньги, зарплаты, аренда, налоги
      awards.ts         # топы журналов, церемония наград
    engine.ts           # тик месяца: порядок обновления систем
    save.ts             # сериализация/десериализация состояния + RNG
    debug.ts            # чит-панель: деньги, точки, ускорение, скрипты тестов
  ui/
    screens/            # Офис, Персонал, Разработка (мастер создания игры),
                        #   Результат релиза, Журналы, Маркетинг, Исследования,
                        #   Железо, Контракты, События, Награды, Главное меню
    components/         # переиспользуемые (стат-бар, таблицы, модалки)
    App.tsx             # роутинг экранов по состоянию
  test/
    formulas.test.ts    # юнит-тесты формул
    balance.test.ts     # скриптовые прохождения: «лучший ход» vs «худший»
    save.test.ts        # roundtrip сохранения
```

**Ключевые принципы:**
- `core` — чистые функции: `engine.tick(state, actions, rng) → state'`. Все изменения состояния — через редьюсеры, это даёт тестируемость и undo.
- Детерминизм: весь RNG — из seeded-генератора, состояние которого хранится в сейве. Одинаковые решения → одинаковые результаты (тесты баланса).
- Контент отделён от кода: таблицы в `core/data/` — дизайнер правит без программирования.
- Журнал действий («лента новостей») — каждый тик пишет события (релиз, рецензия, событие), UI их показывает.

## 3. Модель времени

- **Тик = 1 месяц.** Год = 12 месяцев. Партия = 20 лет (240 тиков) + эндгейм.
- Структура тика (порядок критичен, он же в engine.ts):
  1. Производство: прогресс разработки/отладки (вклад сотрудников, усталость, режим).
  2. Завершения: релизы (→ рецензии журналов, старт продаж), сдача контрактов.
  3. Продажи: по каждой активной игре за месяц (кривая жизни продукта).
  4. Рынок: популярность жанров дрейфует, базы платформ растут, устаревание.
  5. Маркетинг: эффекты рекламы (фанаты/хайп/продажи).
  6. События/контракты: генерация, дедлайны.
  7. Исследования: очки от сотрудников, анлоки.
  8. Финансы: зарплаты, аренда, налог, проценты; банкротство.
  9. Годовые отчёты в январе: топы журналов, церемония наград, пресс-конференции платформ.

## 4. Сохранения

- Один JSON-снапшот `{version, state, rngState, log}` в localStorage; кнопки экспорт/импорт файла.
- Схема версионируется (миграции при изменении формата).
- Автосейв каждый месяц + 3 ручных слота.

## 5. UI-структура (экраны)

1. **Главный экран (Офис)**: компания, календарь, деньги, фанаты; кнопки: Разработка, Персонал, Маркетинг, Исследования, Железо, Контракты, События, Журналы.
2. **Мастер создания игры**: жанр → тип (оригинал/сиквел) → содержание (очки разработки) → тема → платформа → режим (качество/скорость/бюджет+) → назначение сотрудников → старт.
3. **Экран разработки**: прогресс-бары этапов, баги, дедлайн, усталость команды.
4. **Результат релиза**: рецензии 4 журналов, оценка, продажи по месяцам, отзывы.
5. **Персонал**: список, статы, прокачка, обучение, смена карьеры, найм.
6. **Маркетинг**: рекламные кампании, фанаты, хайп.
7. **Исследования/Железо/Контракты/События/Награды** — таблицы и решения.
8. **Чит-панель (debug)**: только в dev-режиме.

## 6. Этапы разработки (milestones)

| M | Что | Приёмка |
|---|---|---|
| **M1** | Ядро: тик месяца, разработка (этапы, очки, баги), отладка, релиз, рецензии, продажи (упрощённая кривая), деньги | Скрипт-прохождение 24 мес. в консоли: компания растёт/банкротится по балансу |
| **M2** | UI: главный экран, мастер создания игры, экран разработки, результат релиза | Играбельный цикл «сделал → выпустил → увидел цифры» |
| **M3** | Персонал: найм, уровни, усталость, смена карьеры, обучение, зарплаты | Прокачка влияет на качество игр |
| **M4** | Платформы, контракты, исследования, реклама, фанаты/хайп | Полный набор решений игрока |
| **M5** | События, топы журналов, награды, ачивки, эндгейм/реиграбельность | Цикл 20 лет проходит без «стены» |
| **M6** | Баланс: скриптовые тесты, тюнинг таблиц, сейвы, миграции | 3 полных прохождения (оптимальное, среднее, плохое) с ожидаемыми исходами |
| **M7** | (Опц.) canvas-вид офиса, анимации, звук | Полировка |

## 7. Тестирование

- **Юнит-тесты формул** (vitest): каждая формула из 09 имеет тест с крайними значениями.
- **Баланс-скрипты**: симуляция «жадный игрок» (всегда лучшие комбо, максимум продаж) должна давать победу к 10–12 году; «случайный» — выживание к 5 году; «бездействие» — банкротство к 3 году.
- **Roundtrip сейвов** и миграции версий.
- Ручные playtest-сессии после каждой M.

## 8. Риски

| Риск | Митигация |
|---|---|
| Неизвестные формулы оригинала → баланс «не тот» | Собственные модели (09), калибровка через скриптовые прохождения (M6) |
| Разрастание скоупа | MVP-скоуп из 00; ++-фичи только после M6 |
| Скука в середине партии | План «кривой открытий» (08): новые платформы/жанры/события с шагом ~2 года |
