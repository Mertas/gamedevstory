# 14. Автопилот (запрос 06.09.2026)

Автопилот включается **только вручную** — кнопкой «Отдать управление» в таскбаре (таймаут
простоя убран 10.09.2026): команда сама решает в чате, какую игру делать дальше, и делает её.
Всё видно на экране: приложения открываются, кнопки нажимаются, летает виртуальная мышка.
Кнопка «Взять управление» выключает авторежим, чат реагирует («босс вернулся»).

## 1. Принцип (по замечанию пользователя)

**API — один запрос со всеми параметрами; UI разруливает показ.**

- GigaChat отдаёт РЕШЕНИЕ одним JSON (жанр, тип, консоль, режим, направление, роли) —
  это и есть «API». Больше LLM ничем не управляет.
- Все движения виртуальной мыши, открытия окон и нажатия — клиентская хореография.
- Финальное нажатие («Начать» в мастере) — НАСТОЯЩЕЕ действие: шлёт обычный
  `start_project` со всеми параметрами. Никаких дублирующих команд серверу.
- Если клиент недоступен (вкладка закрыта/зависла) — сервер применяет действие сам
  по таймауту ~2 с: автопилот работает и без браузера (сцена, а не механика).

## 2. Триггер и завершение

- Триггер (проверка в тикере): `автопилот выкл && !bankrupt && !pendingEvent &&
  !activeGame && week − lastBossActionDay >= 7` → включить: `chatSystem` («Команда
  замечает, что босс пропал…»), пауза не обязательна — время идёт.
- `lastBossActionDay` обновляется на ЛЮБОЕ действие игрока (handle(), кроме
  get_state/set_speed); при этом если автопилот был включён — выключить.
- Кнопка «Взять управление» (таскбар, видна только при автопилоте) шлёт явное
  `take_control` → автопилот выкл + `chatSystem` «Босс вернулся!» + фаза `boss_back`
  (команда реагирует 2–4 репликами: кто радовался, кто делает вид, что не расслаблялся).
- Любое другое действие игрока тоже выключает автопилот (без фазы boss_back — босс
  просто начал кликать).
- Пауза (speed=0) блокирует триггер: игровое время не идёт. Рестарт сервера — автопилот
  выкл (не сохраняется в сейве, поле сессии).

## 3. Цикл автопилота (сервер, `src/server/autopilot.ts`)

Состояние: `on: boolean`, `deciding: boolean`, `decidedThisIdle: boolean`,
`pendingEventSince: number | null` (реальное время появления события, для «театра»).

1. **Решение в чате** (idle, нет активной игры): 2–3 реплики обсуждения в персонах
   (фаза `autopilot_discuss`, обычный nextReply-механизм), затем один вызов
   `decideNextGame(context)`:
   - контекст: команда, деньги, разблокированные жанры/типы (unlock по уровням/тренингам),
     доступные консоли + стоимость, топ комбинаций с градациями S/A/B;
   - ответ — строгий JSON: `{genreId, typeId, consoleId, mode, direction{8 осей},
     proposalStaffId, assignments{program[],graphics[],sound[],debug[]}}`;
   - валидация сервером (жанр/тип открыты, консоль доступна и куплена, денег хватает,
     сценарист существует, роли — реальные id): невалидно или LLM молчит → **фолбэк**:
     `pickBestCombo` + роли из policy.ts (детерминированный «разумный игрок»).
   - после решения: `chatSystem` «Решено: Жанр × Тип на Консоли» + шаг хореографии.
   - **упор направления — весь пул (10.09.2026)**: промпт требует распределить ВСЕ очки
     (1–2 ведущие оси до 8, остаток — в свободные); `fitDirection` добивает недобор до полного
     пула (`topUpDirection`); эффект осей нормирован на 10 очков (09 §2.3: сумма усиливает).
2. **Старт проекта**: сервер НЕ вызывает startProjectAction сразу — ждёт клиентский
   клик «Начать» ≤ 2 с; таймаут → применяет сам (то же самое действие).
3. **Разработка**: события (`pendingEvent`) НЕ резолвятся мгновенно — «театр»: попап
   висит ~1.2 с реального времени (клиент успевает показать попап, мышка нажимает
   «Ок»/«Принять»), затем сервер резолвит политикой (буст — принимать с разумной
   ставкой, продавец — прогнать, Gamedex — лучший доступный стенд, катастрофы/info —
   закрыть, ready_to_release — выпустить). Политика = `createPlayer()` из
   `src/core/sim/policy.ts`, но ВЫЗЫВАЕТСЯ только при `pendingEvent` или
   `activeGame.phase === 'debug' && bugs <= 5` — чтобы бот не стартовал свои проекты
   вместо решений чата. Клиентский клик по кнопке попапа опережает таймаут и является
   настоящим действием.
4. **Релиз**: кнопка «🚀 Выпустить игру» — тот же паттерн (клик клиента / таймаут).
   После релиза `decidedThisIdle` сбрасывается → цикл: снова обсуждение в чате.
5. **Мелкая жизнь**: найм/обучение/реклама/левел-апы — из той же политики (когда она
   вызывается по п.3, она попутно нанимает/учит при деньгах). Специального управления
   не требует.

## 4. Хореография (клиент, `src/ui/AutopilotCursor.tsx`)

- Сервер шлёт шаги: `{type:'autopilot_step', step}` — `{kind:'open', app}` /
  `{kind:'click', target, label}` / `{kind:'chat', text}`. Клиент держит очередь,
  играет по одному.
- Виртуальная мышь: фиксированный курсор (эмодзи-картинка), движение rAF к центру
  целевого элемента (поиск по `[data-autopilot]`), «нажатие» — класс `.w95-autopilot-press`
  (визуальное утопление кнопки, без реального onClick), затем следующий шаг.
- Шаги-«нажатия» бывают двух родов: **косметические** (курсор+утопление, действие уже
  сделано сервером — напр. «Ок» попапа, если серверный таймаут сработал раньше) и
  **реальные** (финальный клик шлёт настоящее действие: «Начать» в мастере,
  «Выпустить игру», кнопки попапов, пока таймаут не сработал). Реальный клик =
  обычный `.click()` по настоящему элементу — дублей не будет, т.к. сервер применяет
  действие только по таймауту, а клиентский клик его опережает/совпадает (действие
  идемпотентно: resolveEventAction по пустому событию — no-op).
- Мастер проекта: перед шагом «Начать» клиент программно заполняет форму визарда
  значениями решения (`store.autopilotFillWizard(plan)` → CodeApp слушает) — по шагам
  визарда видно реально выбранные жанр/тип/консоль/роли; «Начать» активируется и
  настоящий клик шлёт `start_project`.
- Окна открываются через `wm.open(id)` (настоящее открытие, со всеми эффектами).
- Цели: `[data-autopilot="icon-код"]` (иконка стола), `wizard-start` (кнопка «Начать»),
  `release` (кнопка выпуска), `mb-ok` (кнопка «Ок» MessageBox), `mb-accept` (Принять)
  и т.д. — data-атрибуты расставляются в соответствующих компонентах.

## 5. Протокол

- `SessionSnapshot` += `autopilot: boolean` (таскбар показывает кнопку).
- Новые WS-сообщения: сервер→клиент `autopilot_step`; клиент→сервер `take_control`.
- Новые фазы чата: `autopilot_discuss`, `boss_back` (инструкции в chatgen.ts).
- Сейв не меняется (нет новых полей GameState) → SAVE_VERSION не трогаем.

## 6. Тесты

- `validateDecision`: валидное решение проходит; жанр не открыт / консоль не куплена /
  роль с неизвестным id / денег не хватает / нет сценариста → rejected, фолбэк работает.
- Политика под обёрткой не стартует проекты: прогон с activeGame=null и без pendingEvent
  → startProject НЕ вызван; с pendingEvent='boost' → резолвлен.
- Баланс не задет: 69 тестов зелёные (автопилот — серверный слой, движок не меняется).

## 7. Метрики приёмки

- Кнопка «Отдать управление» → чат обсуждает (персоны!) → решение → мышь летает → игра стартует.
- Во время разработки попапы появляются и закрываются «мышкой».
- «Взять управление» → автопилот выкл (кнопка меняется на «Отдать управление»), чат: «босс вернулся».
- Вкладка закрыта → автопилот продолжает работать без UI (таймаут-фолбэки).

## Видимость действий политики (2026-09-11)

Политика автопилота делала «мелкую жизнь» молча: левел-апы и тренинги сотрудников, найм,
реклама, лицензии, переезд офиса, бустеры у продавца — деньги/уровни менялись без движений мыши.
Теперь каждое действие попадает в журнал (`PolicyAction` в `sim/policy`), сервер превращает его
в шаги хореографии (`policySteps`) сразу после резолва события: мышка открывает «Найм»/«Маркетинг»/
«Железо»/«Код», переключает вкладки, выбирает сотрудника карточкой и **нажимает** кнопку действия.

Действие при этом уже применено сервером, поэтому финальное нажатие — «витринное» (cosmetic):
волна + утопление кнопки без повторного клика (иначе тренинг/найм/реклама применились бы дважды).
Реальные клики — только там, где они безопасны и нужны: вкладки, карточки сотрудников, кнопки попапов.
Кнопки попапов (`mb-*`) в очереди шагов имеют приоритет — прыгают вперёд «витринных» шагов,
чтобы мышь успевала нажать до серверного таймаута 2.6с.
