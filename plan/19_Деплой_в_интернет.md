# 19. Выкладка в интернет (VDSina, самый дешёвый тариф)

> Цель: игра доступна друзьям по ссылке, обновления ставятся одной командой, партии не теряются.
> Сервер: VDSina, тариф **5 ₽/сутки** (≈150 ₽/мес), **без бэкапов** → резервные копии делаем сами.
> ОС: Ubuntu 24.04 LTS.

## 1. Что уже готово (проверено по коду)

| Готово | Где |
|---|---|
| Абсолютные URL у клиента (`location.host`, `wss:` при https) | `src/ui/store.ts` — за прокси работает без правок |
| `/api/health` для проверки живости | `src/server/server.ts` |
| Graceful shutdown: SIGTERM/SIGINT сохраняют партии | `server.ts` (`registry.disposeAll()`) |
| Партии в SQLite (`data/users.db`), автосейв, миграции | `users.ts`, `sessions.ts` |
| Все пишущие пути в одном каталоге `data/` | `users.ts`, `save.ts`, `mailer.ts` |
| Статика в git: `public/` → `dist/` (иконки, аватары, скин) | 1240 файлов |
| Контент-БД собирается из `research/*.md` (77 файлов в git) | `pnpm db:build` → `data/gamedev.db` |
| Секреты вне git (`.env` в `.gitignore`) | `.gitignore` |

## 2. Что доделать в репозитории ДО выкладки

1. **`engines` в `package.json`** — `"node": ">=22.13"` (нужен для `node:sqlite` без флага; локально 22.23).
2. **Режим прода для почты** — сейчас `MAIL_MODE=dev` возвращает код восстановления клиенту (`devCode`) и печатает его на экране. На публичном сервере это дыра: любой может запросить сброс по чужому логину и получить код. Перед выкладкой: при `MAIL_MODE=smtp` (или `PROD=1`) код **не отдавать** и на экране не показывать. Варианты — в разделе 7.
3. **Ограничение регистрации / расхода LLM** — иначе любой желающий создаёт аккаунт и жжёт GigaChat-лимит (см. 7).
4. **Простой rate-limit** на `/api/auth/login` и `/api/auth/reset-request` (счётчик попыток по IP+логину, пауза).
5. **Скрипт бэкапа** `scripts/backup.sh` (в репо, ставится в cron): `sqlite3 ... "VACUUM INTO ..."` для `users.db`, копия `gamedev.db` и `mail-out/` в tar.gz с датой + ротация 14 дней.
6. **`.env.example`** — список переменных без значений (чтобы на сервере не забыть ни одну).
7. (по желанию) `README` — короткий раздел «Деплой» со ссылкой на этот файл.

## 3. Каталоги и CI/CD на сервере

```
/srv/gds.git/            — bare-репозиторий (точка приёма push)
/srv/gds/releases/N/     — распакованный релиз (по одному на деплой)
/srv/gds/shared/data/    — БД, письма, контент-БД (ЖИВУТ МЕЖДУ ДЕПЛОЯМИ)
/srv/gds/shared/.env     — секреты (chmod 600)
/srv/gds/current → releases/N   — симлинк, на него смотрит systemd и nginx
/srv/gds/backups/        — свои бэкапы (см. 5)
```

**Деплой = `git push`.** Локально один раз:
```
git remote add prod ssh://gds@<IP>/srv/gds.git
git push prod master          # = выкладка
```
Хук `post-receive` в `/srv/gds.git/hooks/` делает по шагам:
1. раскладывает новый код в `releases/<N>` (`git archive | tar -x`);
2. `ln -sfn /srv/gds/shared/data data` и `cp shared/.env .env`;
3. **гейт:** `pnpm install --frozen-lockfile` → `pnpm check` (типы + линт + 197 тестов). Не прошло — деплой отклоняется, `current` не трогаем;
4. `pnpm build` (tsc + vite → `dist/`);
5. если нет `shared/data/gamedev.db` — один раз `pnpm db:build`;
6. `ln -sfn releases/<N> current` → `systemctl restart gds`;
7. health-check `curl -fsS localhost:3001/api/health` 15 с; если не поднялось — вернуть `current` на предыдущий релиз и перезапустить (автооткат);
8. хранить 3 последних релиза (старые удаляются).

**Откат вручную:** `ssh gds@<IP> /srv/gds/rollback.sh` (то же, что шаг 7, но по команде).

Почему так, а не GitHub Actions: ноль внешних сервисов и минут, работает из РФ без VPN, гейт-тесты на том же железе, что и прод, а `data/` вообще не участвует в деплое (симлинк).

## 4. Первичная настройка сервера (один раз)

```bash
# 1. пользователь и ключ (пароль по SSH выключаем после проверки входа по ключу)
adduser gds && usermod -aG sudo gds
mkdir -p /home/gds/.ssh && chmod 700 /home/gds/.ssh
# локально: ssh-keygen -t ed25519 -f gds_key  → публичный ключ кладём в authorized_keys
# в /etc/ssh/sshd_config: PasswordAuthentication no, PermitRootLogin no → systemctl reload ssh

# 2. Node 22 LTS и pnpm
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs git sqlite3 nginx
sudo corepack enable && corepack prepare pnpm@11 --activate

# 3. каталоги
sudo mkdir -p /srv/gds/{releases,shared/data,backups} && sudo chown -R gds:gds /srv
sudo -u gds git init --bare /srv/gds.git

# 4. сервис
sudo systemctl enable --now gds
```

`/etc/systemd/system/gds.service`:
```ini
[Unit]
Description=Game Dev Story server
After=network.target

[Service]
User=gds
WorkingDirectory=/srv/gds/current
EnvironmentFile=/srv/gds/shared/.env
ExecStart=/usr/bin/pnpm server
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```
В `.env` на сервере: `HOST=127.0.0.1`, `PORT=3001`, ключи GigaChat, `MAIL_MODE`, `MAIL_FROM`. Порт наружу не выставляем — только nginx.

**nginx** (файл `/etc/nginx/sites-available/gds`) — статика и WS через прокси:
```nginx
server {
  server_name game.example.ru;
  client_max_body_size 8m;
  location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;   # для cookie secure
    proxy_read_timeout 3600s;
  }
  location /ws {                                  # WebSocket
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
    proxy_buffering off;
  }
}
```
HTTPS: `sudo certbot --nginx -d game.example.ru` (нужен домен); `ufw allow 22,80,443/tcp` и `ufw enable`.

## 5. Бэкапы (тариф без них — значит наши)

`/srv/gds/backup.sh` + cron `17 4 * * *`:
```bash
#!/bin/bash
set -euo pipefail
D=/srv/gds; S=$D/shared/data; T=$D/backups/$(date +%F)
mkdir -p "$T"
sqlite3 "$S/users.db" ".backup '$T/users.db'"          # безопасно на живой БД
cp "$S/gamedev.db" "$T/" 2>/dev/null || true
tar -czf "$T.tar.gz" -C "$T" . && rm -rf "$T"
find $D/backups -name '*.tar.gz' -mtime +14 -delete     # 2 недели
```
Плюс раз в неделю — скачивать свежий архив к себе на ПК (`scp gds@IP:/srv/gds/backups/*.tar.gz .`): сервер без бэкапов = одна потерянная железка = все партии.

## 6. Домен и HTTPS

**Домен есть: MERTAS.SPACE (nic.ru).** Значит:
1. A-запись `game.mertas.space` (или `@`) → IP сервера VDSina;
2. в `deploy/nginx-gds.conf` заменить `server_name _;` на это имя, `nginx -t && systemctl reload nginx`;
3. `certbot --nginx -d game.mertas.space --redirect` → настоящий HTTPS, продление автоматически таймером certbot.

После этого cookie сессии становится `Secure`, клиент сам переходит на `wss://`. Почта на домене — отдельный план (см. `plan/20_Почта_на_домене.md`).
Резервный путь без домена (DuckDNS/nip.io) остался в `deploy/README.md` — на случай, если DNS-записи менять нельзя.

## 7. Безопасность перед публикацией (по важности)

1. **Код восстановления пароля** (`MAIL_MODE=dev` отдаёт `devCode` клиенту) — на публике это сброс чужого пароля. Варианты: (а) SMTP (настоящее письмо) — правильный; (б) при `MAIL_MODE=smtp` вообще не отдавать код и не показывать его (функция сброса просто выключается); (в) оставить только локально (`HOST=127.0.0.1`) — не наш случай.
2. **Регистрация** — сейчас открыта. Варианты: (а) инвайт-код в `.env` (регистрация только по нему) — рекомендуем для друзей; (б) открытая + суточный лимит LLM-вызовов на игрока; (в) вручную создавать аккаунты.
3. **Rate-limit** на логин/сброс — иначе перебор пароля скриптом.
4. **Порты**: наружу только 80/443, Node — на 127.0.0.1; `ufw`.
5. **Секреты**: `.env` только на сервере (`chmod 600`), в git не попадает; в отчётах не печатать.
6. **GigaChat — один поток**: при 3–4 игроках онлайн реплики встанут в очередь (наша очередь фаз сгладит, но лаг будет заметен). Если станет тесно — платный тариф/юрлицо с RPS.
