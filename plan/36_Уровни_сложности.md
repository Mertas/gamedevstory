# 36. Уровни сложности (M6)

Задание и числа — от лаборатории баланса (`difficulty/README-agent.md`, `difficulty/difficulty-presets.json`,
эксперимент 97, протокол v5: 8 сидов × 7300 дней). Здесь — как это устроено в игре и какие решения приняты.

## Как устроено

- **Числа**: `difficulty/difficulty-presets.json` → `pnpm difficulty:gen` → `src/core/difficulty.ts`
  (автогенерация, руками не править). Ядро: `DIFFICULTY`, `difficultyConfig(id)`, `applyDifficulty(id)`,
  `currentDifficulty()`, `isDifficultyId`.
- **База = «нормальный»**: значения `CONFIG` в `src/core/config.ts` синхронизированы с чемпионом
  лаборатории (13 отличий: DEV_COST_SCALE 2.44, PAYDAY_DAY 372, BOOST_CHANCE 0.651 и т.д.).
  Уровень = база + перекрытия, не три копии конфига.
- **Применение**: `applyDifficulty` вызывается сервером в двух местах — при создании партии
  (`SessionRegistry.create`, до `newGame`) и при загрузке сейва (`SessionRegistry.load`, до старта
  тикера). Ядро само уровни не накладывает (контракт §5.3): `newGame(seed)` работает с данным `CONFIG`.
- **Хранение**: `state.difficulty` в сейве + колонка `saves.difficulty` в `data/users.db`
  (миграция добавляет колонку старым базам; старые сейвы без уровня — «нормальный»).
- **UI**: выбор — в форме новой игры (кнопки с подписями с сервера `/api/difficulties`), уровень
  виден в списке сохранений («лёгкая/обычная/сложная»).

## Решения

- **Смена уровня посреди партии запрещена** — уровень фиксируется при создании и восстанавливается
  при загрузке; никакого пути «поменять на ходу» в UI нет (был вариант явной смены — отложен,
  чтобы не плодить необратимые развилки экономики в живой партии).
- **`PAYDAY_DAY = 372` шире года (365)**: в строгом сравнении `день === PAYDAY_DAY` зарплаты не
  приходили бы никогда (лаборатория, судя по всему, так и мерила — зарплат в её прогонах не было).
  Принято: день праздника приводится по модулю года (372 → **7 апреля**), зарплаты остаются в игре.
  **Флаг для лаборатории**: это ровно случай из §7 README-agenta («числа ведут себя иначе») —
  при следующем перезамере учесть, что PAYDAY_DAY у чемпиона вырожден.
- **Тесты калибровки подтянуты под чемпиона** (цены/баги/скорость отладки считаются от CONFIG,
  а не от старых литералов; тест копилки отладки — про ±полубага округления, а не «>0»).
- **Известное ограничение**: `CONFIG` — один объект на процесс сервера. Если двое пользователей
  одновременно играют партии разных уровней, уровни будут перебивать друг друга (уровень применяется
  при загрузке сессии, «побеждает последний»). Одиночная и последовательная игра — корректно.
  Варианты на будущее: конфиг в состоянии партии (большой рефактор всех чтений `CONFIG.*`) или
  очередь сессий. Для масштаба этой игры (друзья, инвайты) принято как есть.

## Приёмка (по `difficulty/README-agent.md` §8) — как проверено

- `pnpm typecheck` / `pnpm test` — зелёные (323/323, включая `test/difficulty.test.ts`:
  каждый уровень сверяется с `fullConfig` из JSON по всем ключам).
- `pnpm play` — прогнан на трёх уровнях (`GDS_DIFFICULTY=easy|normal|hard pnpm play 42 730`),
  падений нет; результат уровня виден в шапке отчёта.
- Детерминизм: один сид + один уровень дважды → байт-в-байт одинаковый вывод (stdout-хеш совпал
  на всех трёх уровнях).
- Лаборатория: `pnpm probe` в `E:/My/gds-autoresearch` — «совпало: true», мутации `CONFIG`
  (SALES_BASE_RATE ×3, DEV_COST_SCALE) меняют прогон → контракт §5 цел.
- Ключи приёмки на трёх уровнях: START_MONEY 800/500/400, DEV_COST_SCALE 1.9/2.44/3.2,
  BLACKOUT_CHANCE 0.0015/0.00398/0.006, CONTRACT_WEEKLY_RATE 0.01/0.007143/0.005, PAYDAY_DAY 372/372/372 —
  совпадают с JSON (тест).
- Скрытых копий конфига нет: единственный импортный кэш (`WEEKS` в `formulas.ts`) переведён на
  вычисление в момент вызова; грепы модульных чтений `CONFIG` — пустые.
- UI: уровень выбирается на старте новой игры, показывается в списке сохранений, пишется в сейв.

## Обновление чисел

```bash
cd E:/My/gds-autoresearch && PYTHONPATH= python scripts/export-presets.py   # перезапишет JSON
cd E:/My/GameDevStory && pnpm difficulty:gen                                 # перегенерирует difficulty.ts
```
Если лаборатория вернула поправленные числа — прогнать `pnpm check`, тест `difficulty.test.ts`
сверит новое автоматически.
