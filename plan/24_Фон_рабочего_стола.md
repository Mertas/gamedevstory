# PLAN-24. Смена фона рабочего стола

Пункт «Сменить фон…» в контекстном меню рабочего стола (ПКМ по пустому месту), рядом с сортировкой
иконок. Открывает модальное окно в стиле Win95 с превью всех обоев; выбор применяется сразу
(живое превью) и запоминается, «Закрыть» — выход.

## Картинки

Источник — папка Windows 95 Setup 4K (OneDrive, шара пользователя). В репозитории лежат:

- `public/wallpapers/*` — 8 оригиналов (23.4 МБ, вплоть до 6000×4000), имена слагами
  (`win95-setup-4k.jpg`, `win95-setup-4k-bw.jpg`, `original.png`, `keyboard.jpg`, `mouse.jpg`,
  `circuit-board.jpg`, `cables.jpg`, `cds.jpg`).
- `public/wallpapers/thumbs/*.jpg` — превью 480×360 для диалога (14–60 КБ каждое, ~230 КБ на всё).
- `Original.png` (640×480) — это и есть оригинальные обои Windows 95, отдельным пунктом.

`Windows 95 Setup 4K.psd` (196 МБ) в репозиторий **не** кладём: это исходник, а не картинка для
фона, и он раздул бы каждую выкладку.

## Как устроено

- `src/ui/wallpapers.ts` — список обоев (id, подпись, файл, превью), чтение/запись выбора.
- Выбор хранится в `localStorage` (`gds-wallpaper`) — как сортировка иконок; `null` = обычный
  бирюзовый стол.
- Фон ставится инлайн-стилем на `.w95-desktop` (`background-size: cover`), перекрывая градиент
  из CSS.
- Превью генерируются из оригиналов (PIL, качество 82) — чтобы диалог не тянул 23 МБ картинок.

Тест `test/wallpapers.test.ts` проверяет, что список и файлы в репозитории не разъехались
(каждая запись обязана иметь существующий файл и превью).

## Привязка к сейву (по требованию игрока)

Сначала фон хранился в localStorage — то есть за браузером, а не за игроком. Теперь и фон, и
раскладка окон — часть сейва:

- В `GameState` есть необязательное поле `ui` (`src/core/types.ts`): `{ wallpaper, windows }`.
  Игровая логика его не читает — это «как выглядел стол», а не механика. Поле необязательное,
  поэтому старые сейвы открываются без миграции.
- Клиент присылает его сообщением `set_ui` (`actionSetUi`), сервер валидирует
  (`src/server/ui-state.ts`) и сохраняет. Валидация обязательна: клиент — не доверенный источник,
  а значение уезжает во все сохранения игрока (зажим координат, лимит 40 окон, длина id).
- `set_ui` выведен из «действий босса» (`src/server/actions.ts`): иначе перетаскивание окна
  останавливало бы автопилот. Это закреплено тестом в `test/server.test.ts`.
- Менеджер окон (`src/ui/wm.tsx`) поднимает раскладку из сейва при загрузке страницы (открытие
  сейва перезагружает страницу — значит «один раз за сессию» = «для этого сейва») и пишет изменения
  с задержкой 1.2 с, чтобы перетаскивание не писало сейв на каждый пиксель.
- Одноразовый перенос: если у сейва поля `ui` ещё нет, а в браузере выбор был — он уезжает в сейв.
- Позиции иконок (`ui.icons`) — там же: сервер пропускает только ключи, похожие на id приложения
  (`[a-z0-9_-]+`), и зажимает координаты, лимит 60 иконок. В браузере остаётся только зеркало для
  перетаскивания; старый `gds-desk-pos` переносится в сейв один раз.

## Сжатие картинок

Оригиналы ужаты до 1920×1080 (JPEG q85, progressive): 23.43 МБ → **1.59 МБ** (в 14.7 раза), превью
227 КБ. Для фона на экране разницы не видно, а страница больше не тянет 23 МБ. `Original.png` не
трогали — он и так 640×480.
