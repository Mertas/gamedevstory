# AP-09: автопилот нанимает и увольняет сотрудников

Запрос: «Пусть автопилот нанимает и увольняет нужных или хороших сотрудников».

## Решения (согласованы 11.09)
- Кого нанимать: лучшие по статам, приоритет — слабая специализация команды.
- Когда увольнять: только на замену (офис полон и кандидат заметно сильнее слабейшего).
- Метод поиска: самый дорогой доступный по деньгам (сильнее пул), с резервом (до ~800K).
- Размер команды: заполнять офис до вместимости (4/6/8).

## Как было
- policy.ts: найм ОДНОГО СЛУЧАЙНОГО кандидата из дешёвого метода «по знакомству» и только
  в первые 90 дней партии (`state.week < 90`) — студия навсегда застревала на 2/4.
- Увольнять автопилот не умел вовсе; у кнопки «Уволить» не было метки data-autopilot.

## Как стало
- `hireAndFire` (policy.ts): метод — самый дорогой, который тянем (офис + резерв
  `min(800, max(500, money×0.2))`); кандидат — максимум оценки `сумма статов + 1.5 × стат
  слабой специализации команды`; при полном офисе слабейшего меняем на кандидата с оценкой ≥ ×1.2.
- Резерв найма = годовой фонд зарплат (не меньше 500K): найм не съедает деньги на зарплаты
  (живой случай 11.09: 8 нанятых с фондом 3.06M против 1.4M в кассе — студия обнулилась в день зарплат).
- Уволенных автопилотом обратно не нанимаем (защита от «карусели»); механики движка
  (уволенный возвращается в пул кандидатов) не тронуты.
- Журнал политики: `{ type: 'fire', staffId, name }` → шаги мыши «Найм» → «Команда» →
  «Уволить» (витринное нажатие, подпись «Увольняю: Имя»).
- UI: на кнопке «Уволить» — метка `data-autopilot="fire-…"` (без неё мышь не нажмёт).
- `PolicyStats.fires` — счётчик для тестов и баланс-прогонов.

## Проверка
- test/autopilot.test.ts: лучший кандидат (не случайный), замена слабейшего при полном офисе,
  нет увольнений при свободных местах, шаги мыши для fire.
- test/ui-contract.test.ts: метка fire на кнопке «Уволить».
- pnpm typecheck, pnpm check, pnpm build — зелёные.

## Живой прогон (ожидание)
- «Найм → Команда: N/8» растёт до вместимости; в чате/мыши видны «Принимаю в команду: …»
  и «Увольняю: …»; слабые меняются на сильных.
## M7 (16.09.2026): найм — тип поиска решает всё

Запрос: «Переделай найм сотрудников. Сначала нужно выбрать тип поиска. С тебя списываются деньги
и показывается список из возможных кандидатов. И сейчас первые три показывают один и тот же список.
Проанализируй внимательно, должно стать логично.»

### Как было (проблема)
- Три метода — «По знакомству», «Журнал», «Интернет» — тянули ОДИН пул (`Word of Mouth`, 15 человек):
  первые три метода показывали один и тот же список.
- Список показывался БЕСПЛАТНО (деньги списывались только при найме) и был всегда «первые 3
  по порядку в данных» — даже без случайности.

### Как стало (согласовано 16.09)
- **Слои таланта** (`src/shared/hire.ts`, `HIRE_BANDS`): метод = свой круг кандидатов по силе (Σ статов):
  по знакомству (31–46) → журнал (53–71) → интернет (78–115) → профучилище (144–326) →
  день открытых дверей (266–514) → Голливуд (518–1085). Слои покрывают все данные без потерь (тест).
- **Поиск платный**: кнопка «🔍 Искать кандидатов (N K)» списывает деньги сразу; найм из списка —
  только взнос кандидата.
- **Список — результат поиска**: до 3 случайных из слоя, хранится в сейве (`state.activeSearch`),
  живёт до следующего поиска; нанять можно сколько угодно (за каждого — взнос); новый поиск —
  снова платно и даёт новый случайный список.
- **Спец-сотрудники (Mystery Staffers)** — условия из оригинала: Мистер X — 2-й офис;
  Кинг Акбар — 2-й офис + игра-миллионник; Гризли Берингтон — победа в Гран-при;
  Чимпа Зи-Форс — 3 Гран-при; Кайробот — 5 Гран-при. Пока награда не взята — в поиске не появляются.
  После — только в Голливуде и ГАРАНТИРОВАННО в списке, одновременно максимум ОДИН
  (первый по порядку наград). Условия считаются из состояния: офис, `awards.grand`, лучшая игра по копиям.
- Автопилот (AP-09) переведён на новый поток: платный поиск → лучший из списка → найм;
  пустой поиск не оплачивается (бюджетная проверка слоя до поиска).
- Витрина автопилота: «Тип поиска: …» → «Ищу кандидатов» (клик по кнопке поиска помечен cosmetic —
  иначе витринный клик списал бы деньги повторно) → «Принимаю в команду: …».

### Проверка
- `test/hire-pool.test.ts` (15 тестов): покрытие слоёв данными, порядок слоёв по силе, платность
  поиска и повторного поиска, детерминизм (тот же сид = тот же список), найм только из списка
  (только взнос), спецы (порядок открытия, «один в списке», только Голливуд).
- `pnpm check` — 335/335; `pnpm play` — прогоны на трёх уровнях, в журнале «Поиск (…): −N K, кандидатов: 3».
