# План 31. Анимация процесса разработки (окно «Код»)

## 1. Задача

Сделать экран разработки приятным и «профессиональным»: символы летят к полоскам, полоски
заполняются — «как на огонь или воду». Жёсткие требования:
- выдерживать **большие числа** (в партиях уже тысячи очков на направление);
- **не тормозить** при массовых начислениях (сейчас при тысячах символов лагает).

## 2. Диагноз (факты из кода + замеры)

**Как сейчас.** `src/ui/apps/code/Dev.tsx`: разрыв «реальные − показанные − в полёте» спавнит
**1 символ = 1 очко**; каждый символ — DOM-`div` c inline-`<svg>` и `filter: drop-shadow`,
CSS-keyframes `w95-fly` 1.05 c; прилёт — `onAnimationEnd` → 3–4 `setState` на весь `DevStatus`.
Полоска = `v/4` (100 % при 400 очках! — улика «заполняется за 5 секунд»). Ни одного rAF.

**Замер на реальном движке** (пробник на `core/engine`, сейв-разгон ~3 года):
- 45.9 симв./день в среднем, пик 75; **3 399 частиц за проект**; на 8× — **≈368 спавнов/сек** и
  **≈380+ живых DOM-узлов одновременно**;
- бар «400» набивается за **5.4–7.8 с** на 8× (fun — день 43, creativity — 62, graphics — 56),
  при этом финальный fun = 1 843 — половину проекта полоски стоят залитыми.

**Живой бенчмарк в браузере** (Chrome, эта машина):

| Сцена | FPS |
|---|---|
| DOM 500 частиц (svg + drop-shadow) | 60 |
| DOM 2 000 | **30** |
| DOM 5 000 | **7.5** |
| DOM 5 000 без фильтра | 12 |
| Canvas2D 2 000 спрайтов | **60** |
| Canvas2D 5 000 спрайтов | **60** |
| Canvas2D 20 000 | 12 |

`drop-shadow` на частицах стоит ~**+60 % времени кадра**. Вывод: у нас на один–два порядка
меньше частиц, чем нужно WebGL; **Canvas 2D даёт запас ~10×** против наших потребностей.

Дополнительно найдено: утечка `landedRef` между проектами; закрытое/скрытое окно продолжает
спавнить узлы в `display:none` (там `animationend` не приходит — работает только страховочный
таймер, отсюда «выстрелы» пачками при возврате); бэклог задержек `k*0.12` при 500 очках растягивается
на минуты.

## 3. Принципы

1. **Симуляция отделена от рендера.** Игра даёт дельты (вклад дня, points, баги); клиент держит
   лёгкую модель `{показано(float), цель, частицы(пул), вспышки}`; **один rAF-цикл** поверх окна.
   React — только каркас; числа/полоски живут мимо React (refs, `textContent`, `transform`).
2. **Закон честности:** «считаемое — считаем, несчитаемое — чувствуем». Счётчик и бар — истина;
   частицы — поток. Глаз не считает частицы, он чувствует плотность.
3. **Ритм игры = ритм анимации.** Такт = игровой день (1 000 мс на 1×, 125 мс на 8×): замах →
   полёт → впитывание → **покой** (минимум 80–120 мс даже на 8×). Ускорение — сжатие и агрегация,
   не хаос.
4. **Профессионализм = правда движения** (вес, инерция, затухание, пауза), а не «больше частиц».

## 4. Архитектура

1. **Canvas-оверлей** в окне «Код»: `<canvas style="position:absolute; inset:0; pointer-events:none">`
   вместо `fliers.map`. Фигуры вклада (квадрат/треугольник/круг/ромб) и мины рисуются примитивами;
   DPR кэпится на 2; размер = панель окна (не весь десктоп).
2. **Пул частиц** (~512, фикс. массив в ref, freelist): ноль аллокаций в кадре, ноль
   per-particle таймеров и `animationend` — прилёт считается по возрасту в том же rAF.
3. **Один замер геометрии на тик** (панель, бары, строки стаффа через `ResizeObserver`/тик),
   никаких `getBoundingClientRect` в цикле частиц.
4. **Счётчики:** истина из `game.points`; отображаемое число — rAF-интерполяция (ease-out ~400 мс),
   запись `ref.textContent`; обновление цифр **10–20 Гц** (tabular-nums). `setState` на прилёт — ноль.
5. **Спавн из `devContrib`** (доля каждого сотрудника за день уже есть): ≤12 частиц на атрибут за
   тик, вес символа `K = ceil(gap / бюджет)`; остаток от K сразу уходит в целевое число.
   (Опция на будущее: сервер отдаёт готовый «пакет дня» — убирает зеркалирование диффов и делает
   раскладку тестируемой в core.)
6. **Пауза** при скрытой вкладке (`visibilitychange`), свёрнутом/закрытом окне; при возврате —
   ускоренный «догон». Адаптивная деградация: EMA времени кадра > 20 мс → минус 30 % частиц.
7. **Полосы:** `transform: scaleX` (composite-only) вместо `transition: width`; движение — пружина
   (stiffness ≈120, damping ≈20), доезд 300–600 мс с одним малым перелётом.

**Бюджеты:** 150–300 живых частиц, ≤500 спавнов/с, ≤12/атрибут/тик (≤48 за тик), пул 512;
кадр ≤4 мс при бюджете 16.7; число изменений цифр 10–20 Гц; canvas ≤12 МБ VRAM.

**Избегать** (каждый пункт — сегодняшний баг): inline-SVG + `drop-shadow` на частицу; CSS-анимации
на 1 000+ узлов; `will-change` на частицы (layer explosion); таймеры/`animationend` на частицу;
`transition: width`; React-state для летящих объектов; неограниченная очередь задержек.

## 5. Визуальный язык

**Три уровня жизни экрана:** микро (60–250 мс — впитывание: искра, поп цифры); мезо (такт дня:
замах → полёт по кубической Безье с подлётом **по касательной** к бару → впитывание: рябь/поп →
покой); макро (арка: полоски как сюжет — засечки порогов, рекорды).

**Арсенал** (параметры — в меморандуме): easing-набор (замах `(.6,0,.8,.4)`, полёт `(.33,.02,.25,1)`,
впитывание `(.15,.9,.25,1)`, overshoot `(.34,1.56,.64,1)` только для цифр); anticipation (оттяжка
символа за 4 кадра); stagger-гребень (первым летит главный вкладчик) + **РАЗМАЗ ПО ТАКТУ: частицы
дня стартуют не залпом в начале, а в случайные моменты внутри всего тика** — стратифицированный
джиттер (своя случайная точка в своей доле тика: без комков и пустот); на высоких скоростях волны
соседних тактов перекрываются в непрерывный поток. Проверено численно на демке: очередь дня
дренируется волной (40→21→2), живых частиц стабильно ~120, залпов нет; squash&stretch вдоль вектора; след-призраки 2–3 шт. без blur; искры конусом ±60° с
гравитацией; вспышки — энергию отдаём **разнице** («+N» у кромки); дыхание кромки ±1 px/4–6 с.

**Четыре концепции:** A «Медитативный поток» (вода: капли, рябь, струи — «как огонь или воду»);
B «Живая экосистема» (светлячки/сад); C «Терминал» (глифы, перфокарта, долли-матрица — дёшево,
тематично); D «Праздник» (тихая база + эмоции порциями: рекорды, бусты).

**Рекомендация — гибрид: скелет C + материя A + события D.** Вода даёт «залипание» и бесплатно
решает тысячи (струя = агрегация), терминал держит сухой стиль Win95 и дёшев, праздники дают
эмоциональный контраст (Peggle-эффект), иначе неон надоест за неделю. B — задел на будущий «скин».

## 6. Большие числа

- **Три режима по разрыву:** «точный» (≤24/день — 1 символ = 1 очко, как сейчас), «плотный»
  (24–200 — частица = порция 5–10), «поток» (200+ — струя с пакетами, пул ≤120–300).
- **Backpressure:** волны не чаще 1/250 мс; отставание счётчика 0.5–2 с — норма; при возврате в
  окно — ускоренный догон.
- **Числа:** roll-up одометром (старшие разряды статичны, бегут младшие), rate-limit 12–20 Гц,
  разделители разрядов уже есть. Вес дельты («+250») виден, само число — стабильно.
- **Шкала полосок — честная:** верх ≈2 000 (порог «сотки» рецензий, `REVIEW_DIV`/весты), засечки
  порогов; сверх — бар полон, число продолжает расти. Обвал (блэкаут/поломка) — «выдох» с пылью.

## 8. Решения босса (обновлено)

1. **Характер — ПРИНЯТО: гибрид** «вода + сухой терминал, праздники на рекордах».
2. **Люминофор — ПРИНЯТО:** лёгкие 1–2 px подсветки внутри окон можно, хром строго серый.
3. **Счётчик — ПРИНЯТО:** может отставать на 0.5–2 с и плавно догонять.
4. **Шкала полосок — ПРИНЯТО (вариант босса):** динамическая по **рекорду студии по направлению**;
   при превышении рекорда — отдельная анимация празднования (золотая засечка, «РЕКОРД!»), затем
   шкала плавно переставляется на новый уровень.
5. **Агрегация — ПРИНЯТА** (по итогам демки трёх режимов: маленькие темпы — 1 символ = 1 очко,
   большие — порциями).
6. **Звук — открыт к M4:** PC-speaker-тики (WebAudio, 800–2000 Гц, 20–40 мс); политика «тик на
   впитывание» / «аккорд на такт» / «только вехи», mute по умолчанию, если включаем.
7. **Дополнение босса — ПРИНЯТО:** символы летят не залпом в начале такта, а **размазаны случайно
   по всему тику** (стратифицированный джиттер; проверено численно на демке — очередь дня
   40→21→2, живых частиц ~120 постоянно, залпов нет). См. §5 «Размаз по такту».

## 9. M3 — детальный проект «Жизнь и ритм» (обсуждение до M2)

### 9.1 Границы: что уже закрыто в M1 (повторять не надо)

Режимы по разрыву (точный/плотный/поток) — в ядре `planWave`; время полёта уже сжимается от
скорости; динамическая шкала + засечка + базовое «РЕКОРД!» (золотая засечка); размаз по такту;
пауза скрытого окна; бюджет частиц. **Остаток M3 = «жизнь и ритм»:** режимная лестница как
визуальный язык, полное турбо, дыхание простоя, ярусные праздники, засечки/числа на длинной
дистанции, ресурсы 24/7-сессий, каркас деградации.

### 9.2 Режимная лестница (порция → форма)

Плавный микс по «весу» K (лог-шкала, чтобы без рывков на границах 12/200):
- **точный** (K=1): фигурка 3.1 px, 2–3 призрака следа — как сейчас;
- **плотный** (K 2…17): размер 2.6+h·2.8, «люминофор», след 3 призрака;
- **поток** (K 17+): капля вытягивается вдоль вектора (squash & stretch — сжатие по нормали),
  шлейф-линия вместо призраков, прилёт — толчок бара + двойная рябь; форма-фигура сохраняет
  узнаваемость (квадрат/треугольник/круг/ромб), но читается как «струя».

### 9.3 Турбо (0.5×…8×) — что сжимаем, что выключаем

| Скорость | Полёт | Дуга | След | Праздники (wall-clock) |
|---|---|---|---|---|
| 0.5× (½) | 1.10 с | высокая | 3 | полные |
| 1× | 0.85 с | высокая | 3 | полные |
| 2× | 0.70 с | средняя | 3 | полные |
| 4× | 0.55 с | низкая (прямее) | 2 | укороченные (~60%) |
| 8× | 0.42 с | низкая | 2 | быстрые (~35%), без очереди |

Правила: скорость сменилась в полёте — частица доживает «по-старому»; счётчик и полоски уже
не зависят от скорости (догон — wall-clock); на 8× волны соседних тактов переплетаются в
непрерывный поток (уже тактически есть — довести параметрами).

**Референсная проверка (меморандум plan/33):** Balatro сжимает именно анимации (0.5/1/2/4, 4× —
рабочий режим у игроков); Civ VI на быстрых скоростях именно ВЫКЛЮЧАЕТ анимации, а не разгоняет;
Anno держит потолок 3× (выше рвётся читаемость) — наш 8× компенсируем агрегацией и сжатием;
Football Manager и idle-жанр агрегируют вместо ускорения. Ограничение: **не сжимать ниже
250–300 мс** (порог читаемости события).

**Контракт ядра:** `celebrationDurations(speed)` и `ambientEnabled(speed)` — чистые функции рядом
с `planWave`/`barScaleTop`/`recordThreshold`, с юнит-тестами на монотонность от скорости
(как тестируется вес K). Микро-фидбек (вспышки, hitstop 20–50 мс) скоростью НЕ масштабируется.

### 9.4 Дыхание простоя (idle)

- **Тихий планировщик:** нет частиц и событий > 2 с → кадр уходит с 60 fps на «ленивый» 2–4 fps;
  любое событие (волна вклада, мина, праздник, ввод, hover) мгновенно возвращает 60. Порог входа —
  по состояниям движка, а не по таймеру-эвристике; выход — по факту появления работы.
- **Постоянная жизнь (при любом fps):** **бюджет 2 амбиент-цикла + 1 редкий объект** (правило из
  меморандума; одновременное мигание N индикаторов = «гирлянда», бесит): (1) кромки баров ±0.5 px
  синусом (период 4–6 с, у каждого направления своя фаза); (2) штриховка бара медленно «течёт»
  (background-position); «пылинки» сливаются с дыханием (не третий цикл); точка автосейва в углу
  панели (1 px, раз в 2 с) — статусная, не «сказочная». Амбиент — CSS/дешёвый канвас, живёт в
  тихом режиме. Амплитуды «на грани заметности»: ≤1 px, ≤1–2% яркости; движение в зоне чтения
  запрещено (периферийное зрение само ловит движение — центр беречь под события).
- **Пауза ⏸:** жизнь не останавливается (видно, что игра жива), у часов трея — «zZz» (DOM, дёшево).
- **Микро-скринсейвер:** после 45–60 с полной тишины в правом нижнем углу панели — крошечная
  сценка 60–80 px: (вариант A) пиксельная труба капает в лужу; (вариант B) ничего, только дыхание.
  На выбор босса (вопрос 1).

# План 31. Анимация процесса разработки (окно «Код»)

Статус: **на согласовании у босса** (вопросы в §8). Код не менять до утверждения.
Свод: ассистент + 3 агента (архитектурный анализ, визуальная концепция, производительность).

---

## 1. Задача

Сделать экран разработки приятным и «профессиональным»: символы летят к полоскам, полоски
заполняются — «как на огонь или воду». Жёсткие требования:
- выдерживать **большие числа** (в партиях уже тысячи очков на направление);
- **не тормозить** при массовых начислениях (сейчас при тысячах символов лагает).

## 2. Диагноз (факты из кода + замеры)

**Как сейчас.** `src/ui/apps/code/Dev.tsx`: разрыв «реальные − показанные − в полёте» спавнит
**1 символ = 1 очко**; каждый символ — DOM-`div` c inline-`<svg>` и `filter: drop-shadow`,
CSS-keyframes `w95-fly` 1.05 c; прилёт — `onAnimationEnd` → 3–4 `setState` на весь `DevStatus`.
Полоска = `v/4` (100 % при 400 очках! — улика «заполняется за 5 секунд»). Ни одного rAF.

**Замер на реальном движке** (пробник на `core/engine`, сейв-разгон ~3 года):
- 45.9 симв./день в среднем, пик 75; **3 399 частиц за проект**; на 8× — **≈368 спавнов/сек** и
  **≈380+ живых DOM-узлов одновременно**;
- бар «400» набивается за **5.4–7.8 с** на 8× (fun — день 43, creativity — 62, graphics — 56),
  при этом финальный fun = 1 843 — половину проекта полоски стоят залитыми.

**Живой бенчмарк в браузере** (Chrome, эта машина):

| Сцена | FPS |
|---|---|
| DOM 500 частиц (svg + drop-shadow) | 60 |
| DOM 2 000 | **30** |
| DOM 5 000 | **7.5** |
| DOM 5 000 без фильтра | 12 |
| Canvas2D 2 000 спрайтов | **60** |
| Canvas2D 5 000 спрайтов | **60** |
| Canvas2D 20 000 | 12 |

`drop-shadow` на частицах стоит ~**+60 % времени кадра**. Вывод: у нас на один–два порядка
меньше частиц, чем нужно WebGL; **Canvas 2D даёт запас ~10×** против наших потребностей.

Дополнительно найдено: утечка `landedRef` между проектами; закрытое/скрытое окно продолжает
спавнить узлы в `display:none` (там `animationend` не приходит — работает только страховочный
таймер, отсюда «выстрелы» пачками при возврате); бэклог задержек `k*0.12` при 500 очках растягивается
на минуты.

## 3. Принципы

1. **Симуляция отделена от рендера.** Игра даёт дельты (вклад дня, points, баги); клиент держит
   лёгкую модель `{показано(float), цель, частицы(пул), вспышки}`; **один rAF-цикл** поверх окна.
   React — только каркас; числа/полоски живут мимо React (refs, `textContent`, `transform`).
2. **Закон честности:** «считаемое — считаем, несчитаемое — чувствуем». Счётчик и бар — истина;
   частицы — поток. Глаз не считает частицы, он чувствует плотность.
3. **Ритм игры = ритм анимации.** Такт = игровой день (1 000 мс на 1×, 125 мс на 8×): замах →
   полёт → впитывание → **покой** (минимум 80–120 мс даже на 8×). Ускорение — сжатие и агрегация,
   не хаос.
4. **Профессионализм = правда движения** (вес, инерция, затухание, пауза), а не «больше частиц».

## 4. Архитектура

1. **Canvas-оверлей** в окне «Код»: `<canvas style="position:absolute; inset:0; pointer-events:none">`
   вместо `fliers.map`. Фигуры вклада (квадрат/треугольник/круг/ромб) и мины рисуются примитивами;
   DPR кэпится на 2; размер = панель окна (не весь десктоп).
2. **Пул частиц** (~512, фикс. массив в ref, freelist): ноль аллокаций в кадре, ноль
   per-particle таймеров и `animationend` — прилёт считается по возрасту в том же rAF.
3. **Один замер геометрии на тик** (панель, бары, строки стаффа через `ResizeObserver`/тик),
   никаких `getBoundingClientRect` в цикле частиц.
4. **Счётчики:** истина из `game.points`; отображаемое число — rAF-интерполяция (ease-out ~400 мс),
   запись `ref.textContent`; обновление цифр **10–20 Гц** (tabular-nums). `setState` на прилёт — ноль.
5. **Спавн из `devContrib`** (доля каждого сотрудника за день уже есть): ≤12 частиц на атрибут за
   тик, вес символа `K = ceil(gap / бюджет)`; остаток от K сразу уходит в целевое число.
   (Опция на будущее: сервер отдаёт готовый «пакет дня» — убирает зеркалирование диффов и делает
   раскладку тестируемой в core.)
6. **Пауза** при скрытой вкладке (`visibilitychange`), свёрнутом/закрытом окне; при возврате —
   ускоренный «догон». Адаптивная деградация: EMA времени кадра > 20 мс → минус 30 % частиц.
7. **Полосы:** `transform: scaleX` (composite-only) вместо `transition: width`; движение — пружина
   (stiffness ≈120, damping ≈20), доезд 300–600 мс с одним малым перелётом.

**Бюджеты:** 150–300 живых частиц, ≤500 спавнов/с, ≤12/атрибут/тик (≤48 за тик), пул 512;
кадр ≤4 мс при бюджете 16.7; число изменений цифр 10–20 Гц; canvas ≤12 МБ VRAM.

**Избегать** (каждый пункт — сегодняшний баг): inline-SVG + `drop-shadow` на частицу; CSS-анимации
на 1 000+ узлов; `will-change` на частицы (layer explosion); таймеры/`animationend` на частицу;
`transition: width`; React-state для летящих объектов; неограниченная очередь задержек.

## 5. Визуальный язык

**Три уровня жизни экрана:** микро (60–250 мс — впитывание: искра, поп цифры); мезо (такт дня:
замах → полёт по кубической Безье с подлётом **по касательной** к бару → впитывание: рябь/поп →
покой); макро (арка: полоски как сюжет — засечки порогов, рекорды).

**Арсенал** (параметры — в меморандуме): easing-набор (замах `(.6,0,.8,.4)`, полёт `(.33,.02,.25,1)`,
впитывание `(.15,.9,.25,1)`, overshoot `(.34,1.56,.64,1)` только для цифр); anticipation (оттяжка
символа за 4 кадра); stagger-гребень (первым летит главный вкладчик) + **РАЗМАЗ ПО ТАКТУ: частицы
дня стартуют не залпом в начале, а в случайные моменты внутри всего тика** — стратифицированный
джиттер (своя случайная точка в своей доле тика: без комков и пустот); на высоких скоростях волны
соседних тактов перекрываются в непрерывный поток. Проверено численно на демке: очередь дня
дренируется волной (40→21→2), живых частиц стабильно ~120, залпов нет; squash&stretch вдоль вектора; след-призраки 2–3 шт. без blur; искры конусом ±60° с
гравитацией; вспышки — энергию отдаём **разнице** («+N» у кромки); дыхание кромки ±1 px/4–6 с.

**Четыре концепции:** A «Медитативный поток» (вода: капли, рябь, струи — «как огонь или воду»);
B «Живая экосистема» (светлячки/сад); C «Терминал» (глифы, перфокарта, долли-матрица — дёшево,
тематично); D «Праздник» (тихая база + эмоции порциями: рекорды, бусты).

**Рекомендация — гибрид: скелет C + материя A + события D.** Вода даёт «залипание» и бесплатно
решает тысячи (струя = агрегация), терминал держит сухой стиль Win95 и дёшев, праздники дают
эмоциональный контраст (Peggle-эффект), иначе неон надоест за неделю. B — задел на будущий «скин».

## 6. Большие числа

- **Три режима по разрыву:** «точный» (≤24/день — 1 символ = 1 очко, как сейчас), «плотный»
  (24–200 — частица = порция 5–10), «поток» (200+ — струя с пакетами, пул ≤120–300).
- **Backpressure:** волны не чаще 1/250 мс; отставание счётчика 0.5–2 с — норма; при возврате в
  окно — ускоренный догон.
- **Числа:** roll-up одометром (старшие разряды статичны, бегут младшие), rate-limit 12–20 Гц,
  разделители разрядов уже есть. Вес дельты («+250») виден, само число — стабильно.
- **Шкала полосок — честная:** верх ≈2 000 (порог «сотки» рецензий, `REVIEW_DIV`/весты), засечки
  порогов; сверх — бар полон, число продолжает расти. Обвал (блэкаут/поломка) — «выдох» с пылью.

## 8. Решения босса (обновлено)

1. **Характер — ПРИНЯТО: гибрид** «вода + сухой терминал, праздники на рекордах».
2. **Люминофор — ПРИНЯТО:** лёгкие 1–2 px подсветки внутри окон можно, хром строго серый.
3. **Счётчик — ПРИНЯТО:** может отставать на 0.5–2 с и плавно догонять.
4. **Шкала полосок — ПРИНЯТО (вариант босса):** динамическая по **рекорду студии по направлению**;
   при превышении рекорда — отдельная анимация празднования (золотая засечка, «РЕКОРД!»), затем
   шкала плавно переставляется на новый уровень.
5. **Агрегация — ПРИНЯТА** (по итогам демки трёх режимов: маленькие темпы — 1 символ = 1 очко,
   большие — порциями).
6. **Звук — открыт к M4:** PC-speaker-тики (WebAudio, 800–2000 Гц, 20–40 мс); политика «тик на
   впитывание» / «аккорд на такт» / «только вехи», mute по умолчанию, если включаем.
7. **Дополнение босса — ПРИНЯТО:** символы летят не залпом в начале такта, а **размазаны случайно
   по всему тику** (стратифицированный джиттер; проверено численно на демке — очередь дня
   40→21→2, живых частиц ~120 постоянно, залпов нет). См. §5 «Размаз по такту».

дистанции, ресурсы 24/7-сессий, каркас деградации.

### 9.2 Режимная лестница (порция → форма)

Плавный микс по «весу» K (лог-шкала, чтобы без рывков на границах 12/200):
- **точный** (K=1): фигурка 3.1 px, 2–3 призрака следа — как сейчас;
- **плотный** (K 2…17): размер 2.6+h·2.8, «люминофор», след 3 призрака;
- **поток** (K 17+): капля вытягивается вдоль вектора (squash & stretch — сжатие по нормали),
  шлейф-линия вместо призраков, прилёт — толчок бара + двойная рябь; форма-фигура сохраняет
  узнаваемость (квадрат/треугольник/круг/ромб), но читается как «струя».

### 9.3 Турбо (0.5×…8×) — что сжимаем, что выключаем

| Скорость | Полёт | Дуга | След | Праздники (wall-clock) |
|---|---|---|---|---|
| 0.5× (½) | 1.10 с | высокая | 3 | полные |
| 1× | 0.85 с | высокая | 3 | полные |
| 2× | 0.70 с | средняя | 3 | полные |
| 4× | 0.55 с | низкая (прямее) | 2 | укороченные (~60%) |
| 8× | 0.42 с | низкая | 2 | быстрые (~35%), без очереди |

Правила: скорость сменилась в полёте — частица доживает «по-старому»; счётчик и полоски уже
не зависят от скорости (догон — wall-clock); на 8× волны соседних тактов переплетаются в
непрерывный поток (уже тактически есть — довести параметрами).

**Референсная проверка (меморандум plan/33):** Balatro сжимает именно анимации (0.5/1/2/4, 4× —
рабочий режим у игроков); Civ VI на быстрых скоростях именно ВЫКЛЮЧАЕТ анимации, а не разгоняет;
Anno держит потолок 3× (выше рвётся читаемость) — наш 8× компенсируем агрегацией и сжатием;
Football Manager и idle-жанр агрегируют вместо ускорения. Ограничение: **не сжимать ниже
250–300 мс** (порог читаемости события).

**Контракт ядра:** `celebrationDurations(speed)` и `ambientEnabled(speed)` — чистые функции рядом
с `planWave`/`barScaleTop`/`recordThreshold`, с юнит-тестами на монотонность от скорости
(как тестируется вес K). Микро-фидбек (вспышки, hitstop 20–50 мс) скоростью НЕ масштабируется.

### 9.4 Дыхание простоя (idle)

- **Тихий планировщик:** нет частиц и событий > 2 с → кадр уходит с 60 fps на «ленивый» 2–4 fps;
  любое событие (волна вклада, мина, праздник, ввод, hover) мгновенно возвращает 60. Порог входа —
  по состояниям движка, а не по таймеру-эвристике; выход — по факту появления работы.
- **Постоянная жизнь (при любом fps):** **бюджет 2 амбиент-цикла + 1 редкий объект** (правило из
  меморандума; одновременное мигание N индикаторов = «гирлянда», бесит): (1) кромки баров ±0.5 px
  синусом (период 4–6 с, у каждого направления своя фаза); (2) штриховка бара медленно «течёт»
  (background-position); «пылинки» сливаются с дыханием (не третий цикл); точка автосейва в углу
  панели (1 px, раз в 2 с) — статусная, не «сказочная». Амбиент — CSS/дешёвый канвас, живёт в
  тихом режиме. Амплитуды «на грани заметности»: ≤1 px, ≤1–2% яркости; движение в зоне чтения
  запрещено (периферийное зрение само ловит движение — центр беречь под события).
- **Пауза ⏸:** жизнь не останавливается (видно, что игра жива), у часов трея — «zZz» (DOM, дёшево).
- **Микро-скринсейвер:** после 45–60 с полной тишины в правом нижнем углу панели — крошечная
  сценка 60–80 px: (вариант A) пиксельная труба капает в лужу; (вариант B) ничего, только дыхание.
  На выбор босса (вопрос 1).

- **T2 — «все четыре рекорда» студии** (1 раз за партию): 1.5 с золотой дождь над панелью + штамп
  «СУПЕР-РЕКОРД СТУДИИ» у шапки + тряска 1 px по вертикали 0.3 с **только контента панели** (не окна).
- **T3 — вехи прогресса 25/50/75%:** флажок на полосе прогресса + микро-вспышка процента;

### 9.7 Долгие сессии (автопилот 24/7 в открытом окне)

**КРИТИЧНО из инженерного аудита (полный отчёт: plan/32, скрипт soak-теста там же):**
- **Утечка `pending` в фоновой вкладке** — защита «скрытого окна» не ловит браузерный фон
  (панель не display:none, размеры на месте): rAF в фоне не идёт (дренаж стоит), а `setWave`
  продолжает копить очередь → 8×: **≈155 МБ/час**, OOM вкладки. Лечение (3 слоя): `suspend()`
  по `visibilitychange` (очистка очереди без зачисления — числа догонят при возврате),
  **стоп-лимит MAX_PENDING = 96** (при превышении — мгновенное зачисление), обязательный
  `measure()` при возврате.
- **Watchdog на rAF:** исключение внутри `frame()` сегодня убивает анимацию навсегда (окно
  переоткрывать) — `try/finally` + перезапуск при `raf===0 && !dead`.
- **Стоп-лимиты эффектов:** `SPARK_CAP≈600`, `RIPPLE_CAP≈120`, `GHOST_CAP≈24` (1 призрак на
  атрибут за такт), `ctx.font` — раз на кадр (сейчас строка на каждый из ~211 `fillText`).
- **Компакция массивов кадра** на месте (сейчас 4 новых массива/кадр ≈ 864 тыс./час — GC-шум).
- Косметика: класс `.beat` не снимается при `setProject` — золотая засечка «переезжает» в новый
  проект; снимать вместе с `w95-attr-flash`.

- Тихий планировщик (9.4) — главный ресурс-сейв: простой экран не жжёт CPU; дизайн режимов
  active/quiet/asleep, `hasWork(now)` (7 условий), мгновенный `wake()` по вводу/событиям —
  в plan/32 §3;
- **soak-тест 60 минут:** раз в минуту в лог — heap (`performance.memory`), EMA кадров, живые
  частицы, размеры массивов; критерий деградации: heap растёт монотонно >10%, fps < 55, живые
  частицы выше бюджета; деградация EMA по кадрам (заготовка — в M3, включение — M4).

- **Модули:** `src/shared/wtc.ts` (чистое ядро: события-моменты, выбор сэмпла, план очереди,

- **Точка подключения:** `Dev.tsx` — `eng.onLand = () => wtc.onAbsorb()` (вместо `sfx.drop()`).
  «Эффекты: минимум» глушит Баха; громкость = общий уровень звука («тихо» по умолчанию).
- **Честные голоса:** событие = момент партитуры (аккорд бьёт вместе, выдержанные ноты тянутся
  по темпу пьесы). Ноты не пропускаются; при переполнении очереди (впереди > 2.2 с) нота
  пропускается; минимум между событиями 45 мс (потолок ~22 соб/с на 4×/8×).
- **Ассеты** (`public/wtc/`, 270 КБ): ноты BWV 846, 847 (прелюдия+фуга), 850 — JSON из kern

- **Парсер (важно):** слияние голосов `*v` в kern — серия из k подряд режет (k−1), а не k;
  плюс самокоррекция по числу полей. До фикса молча терялись выдержанные басы финалов
  (847: +4 ноты, 850: +13 нот). Симптом был «одна нотка не соответствует» в финале 847.

## M5.2 — пачки очков: каденции вместо мелодии (v1.20.2/1.20.3)
- **Пачка** = скачок очков при пустом devContrib: так приходят и стартовый вклад сценариста (фаза «предложение»), и успешное «улучшение» (boost: game.points[key] += gain напрямую, gain 25–50 очков). Порог детекта — ≥3 очка.
- Такая волна уходит в движок с флагом silent (частицы летят, нот не двигают), а вместо мелодии один раз играет `wtc.chordBurst()` — три аккорда в текущей тональности (`WTC_BURST_CHORDS` в shared/wtc.ts: iv–V–i для минора, IV–V–I для мажора, тесное расположение).
- Мелодия идёт только от вклада дня (dc>0) — «обычный режим». M5.1 (silent до «первой настоящей недели») снят: devContrib непустой почти с самого старта, признак не работал.
- `chordBurst` при незагруженных сэмплах ставит pendingBurst и доигрывает каденцию после загрузки (стартовая каденция приходит раньше сэмплов — иначе теряется).
- **Диагностика нот (живьём, без деплоя):** обернуть `__gdsWtc.onAbsorb` (стек/счётчики) + хук на `__gdsWs` message ({week, activeGame.phase, devContrib.length}); залп на старте ловится как 15–20 событий за ~1с.
- **Фон и музыка:** dev-движок на rAF стоит в скрытой вкладке — ноты глохнут при ЛЮБОЙ настройке. «Выключать музыку в неактивной вкладке»: 'on' → silence; 'off' («не выключать») → `visibilityChanged()` заводит фоновый таймер 900мс, ~2 ноты/с (`bgNotes()`, после долгого фона — не залп).
